# T3 Code — orchestration v2

T3 is an Orchestrator Source. A Capture preserves one Orchestrator Thread's native evidence; its exact Provider Thread identity links to a Codex or Claude Session. It adds Thread titles, Project/worktree/model/runtime facts, Runs, checkpoints and orchestration history. It never creates a duplicate T3 Conversation.

When no Host has ever Captured a linked provider Session, an unambiguous Link may recover its Dialog from the Thread's projected Messages ([ADR-0007](../adr/0007-recovered-sessions-from-orchestrator-dialog.md)). The recovered identity stays Codex/Claude and renders `session-recovered-via`. A real provider Capture supersedes recovery. T3-only delegation and native-child relation rows are preserved as evidence; they do not currently create canonical Subagent parent links.

## Live Store authority

`<t3-root>/userdata/statev2.sqlite` is mandatory for an installed/configured T3 Store. The default base is `~/.t3`. `state.sqlite` is abandoned Thread state and must never be used as a fallback. If only that legacy file exists, report an incompatible Store. A missing default installation is normal; an explicitly configured missing Store is a Source failure.

Use one read-only, WAL-aware transaction for enumeration and each Capture. Native Stores must remain unmodified. Production diagnosis uses SQLite read-only backups into `temp.local`, never unsafe copies of a live main database without its WAL.

Inside the v2 database, `projection_projects` and Project-stream `orchestration_events` are still authoritative: the Project service did not move its schema. Never select legacy **Thread** events or projections from those unprefixed tables.

## Capture allowlist

Every selected row preserves all columns, exact SQLite types, and exact values. JSON columns remain JSON text; blobs use base64. Unknown added columns/events survive automatically. Do not scan arbitrary tables: auth, command receipts, effect outboxes, settings, caches and diagnostics are excluded.

| Table | Selection/order |
|---|---|
| `projection_projects` | exact Project id |
| `orchestration_v2_projection_threads` | exact Thread id |
| `orchestration_v2_projection_provider_threads` | Thread id; Provider Thread id |
| `orchestration_v2_projection_runs` | Thread id; ordinal, Run id |
| `orchestration_v2_projection_run_attempts` | Thread id; Run, attempt ordinal/id |
| `orchestration_v2_projection_nodes` | Thread id; node id |
| `orchestration_v2_projection_provider_turns` | Thread id; Provider Thread, ordinal/id |
| `orchestration_v2_projection_runtime_requests` | Thread id; creation time/id |
| `orchestration_v2_projection_messages` | Thread id; creation time, Message id |
| `orchestration_v2_projection_plans` | Thread id; plan id |
| `orchestration_v2_projection_turn_items` | Thread id; ordinal, item id |
| `orchestration_v2_projection_checkpoint_scopes` | Thread id; scope id |
| `orchestration_v2_projection_checkpoints` | Thread id; capture time, checkpoint id |
| `orchestration_v2_projection_context_handoffs` | Thread id; handoff id |
| `orchestration_v2_projection_subagents` | Thread id; Subagent id |
| `orchestration_v2_events` | Thread id; sequence |
| `orchestration_events` | Project aggregate/stream only; sequence |
| `orchestration_v2_projection_provider_session_bindings` | Thread id; provider-session/Thread id |
| `orchestration_v2_projection_provider_sessions` | direct Thread id **or** exact binding; provider-session id |
| `orchestration_v2_projection_context_transfers` | source **or** target Thread id; transfer id |
| `orchestration_v2_legacy_imports` | Thread id; import status/timestamps |

The listed order is deterministic Capture order. Shared provider-session rows can have a null `thread_id`; their binding rows are required to select the process facts for each bound Thread. They are never Session identity evidence.

The schema contract requires every allowlisted table, selected primary key, predicate/order column, and decoded field. `src/adapters/t3/schema.rs` defines the exact contract. Validate before enumerating even an empty Store. Missing required tables/columns explicitly fail the Source, preserve its Bookmark, and allow other Sources to continue. Unknown added tables are excluded until explicitly approved as relevant native evidence.

T3 migration 63 (`apps/server/src/persistence/Migrations/063_DropUnusedV1Projections.ts`) removes the obsolete v1 `checkpoint_diff_blobs` table. Live reads exclude it even if an older Store still contains it. T3 runs its migrations at persistence startup (`Sqlite.ts`); no separate pre-migration live reader is needed. Current checkpoint evidence comes from the v2 scope/checkpoint projections defined in migration 55 and `packages/contracts/src/orchestrationV2.ts` (`OrchestrationV2CheckpointScope`, `OrchestrationV2Checkpoint`). Historical Capture decoding remains independent and preserves v1 evidence.

## Exact provider identity

Decode `orchestration_v2_projection_provider_threads.payload_json.nativeThreadRef`:

```json
{"driver":"codex","nativeId":"<native-thread-id>","strength":"strong"}
```

| Driver | Native identity |
|---|---|
| `codex` | nonempty `nativeId`, exactly the rollout Session id |
| `claudeAgent` | UUID-shaped `nativeId`, exactly the Claude Session id |

Only strong references qualify. Missing, malformed, weak or unsupported references produce explicit unresolved facts. Never infer identity from T3 Thread ids, provider-session process ids, timestamps, titles, paths, prompt text, or old resume cursors.

A Provider Thread with `owner_node_id` belongs to a native child: do not attach its Session to the enclosing root Thread. All root identity facts are retained. Multiple distinct identities on the winning Thread are ambiguous: the existing resolver refuses Augmentation/recovery rather than selecting one identity and misassigning mixed Dialog. Unsupported/unproven mappings remain preserved in the Capture.

The observed v2 Store has Threads with projected Dialog but no Provider Thread rows. Preserve those Threads, leave them unlinked, and do not use old live mappings to fill the gap.

## Projection extraction

Thread scalar columns provide identity, title and timestamps. Thread `payload_json` carries model selection, branch/worktree, provider instance, runtime/interaction modes, pin/settle state and linked PR. Message `payload_json.text` is the T3-visible Dialog; `role` and `created_at` are scalar columns. Runs replace legacy turns; turn items and Subagent projections retain activity payloads. Every other selected row remains durable even when not decoded into a current canonical field.

Malformed required Message payload/text is an extraction error, never empty Dialog. Attachments come from Message `payload_json.attachments`, not legacy `attachments_json`. Resolve only known file/image descriptors inside the flat `userdata/attachments` namespace; reject traversal, separators, symlinks and non-regular files, enforce descriptor size and the 100 MiB limit, and stream exact bytes with before/after stat checks. Missing/unreadable attachments remain captured statuses and retry. Rebuild never reads live attachments.

## Revisions and durable format

Capture paths remain:

```text
captures/<host>/t3/<thread-id>.ndjson.zst
captures/<host>/t3/<thread-id>.meta.json
```

Typed NDJSON row records include table, primary key, column names/types/values. Attachment records and chunks follow the rows. Adapter revision 5 excludes obsolete v1 checkpoint blobs from live Capture; revision 4 captures v2 import markers; revision 3 is the fixed v2 generation boundary; revision 1/2 Captures remain decodable by the historical Capture decoder, without old Store discovery.

`sourceMtimeMs` is the maximum relevant native timestamp; `sourceSize` is a deterministic typed-row/attachment-metadata digest, not a byte count. T3 first compares storage generation: Adapter revisions 1–2 identify the legacy Store, and revision 3 is the fixed v2 boundary. A v2 import can have a lower timestamp because it omits legacy runtime/event clocks. A generation advance becomes current while retaining the complete old body/sidecar as a Prior Revision; older-generation Bundle arrivals cannot supersede v2. Global projection election uses the same generation boundary before native timestamps. Within v2, native timestamp advance or equal-time digest change supersedes; timestamp rollback is refused. Exact timestamp/digest equality skips unchanged work. A required Adapter refresh must rewrite its Capture even at an equal native revision. Local revision gates and Bundle ingest retain the common logical SQLite supersede policy.

Remote incremental Export gates on the Source Bookmark. Before deploying, **back up the complete Archive**, including Captures and Prior Revisions, Digests, lead files, config and Bookmarks. Rollback is not clean: the old binary does not understand storage generations and cannot safely continue collecting into the upgraded Archive. Restore the pre-deploy backup together with the old binary if rollback is necessary.

After deploying, run:

```sh
agent-sessions pull --archive /srv/example/agent-sessions/archive --full-source t3
agent-sessions rebuild --archive /srv/example/agent-sessions/archive
```

`--full-source t3` resets only T3's Bookmark on every configured Host under the Pull writer lock. Remote Export therefore omits `--since`; local enumeration also covers every Thread. Other Sources retain their normal incremental windows. Ingest is idempotent, so repeated backfills reuse unchanged Captures. Failures leave the affected Source's retry window open. Rebuild alone cannot fetch absent v2 evidence.

Fleet deployment compares `--version`, now `agent-sessions 0.2.0 (<git-hash>)`; development builds append a dirty-source fingerprint. Equal package versions with different build identities trigger redeployment.

## Imported Threads and durable legacy evidence

A captured `orchestration_v2_legacy_imports` row proves that a v2 Thread is an imported shell. When it has no root Provider Thread row, extraction carries exact link facts and missing recovery Dialog from its latest **legacy Prior Revision**, selected by `capturedAtMs` for the same `(host, thread_id)`. Sidecar identity mismatches or unreadable retained evidence are explicit errors. Preserve these Prior Revisions in backups: local Pull and central Bundle settlement retain them before extraction, and Rebuild consumes the same evidence. Root Provider Thread rows (including malformed/weak references) prevent carry-forward; no legacy identity can override a new native reference. No unprefixed live Thread tables or frozen runtime tables are queried. This keeps the original proven identities rather than introducing another live schema dependency.

## Title Write-back

Unfiltered title planning reports T3 errors per Source while retaining Claude/Codex plans. Explicit `--source t3` errors remain fatal. Bare Bundle Export similarly reports/counts Source failures and exports healthy Sources.

Planning/revalidation reads `statev2.sqlite.orchestration_v2_projection_threads.title`, including schema validation. The installed v2 build removed `/api/orchestration/dispatch` and renamed `thread.meta.update` to `thread.metadata.update`.

Use `userdata/server-runtime.json` version 1 for the running server origin, and an existing paired `T3_BEARER_TOKEN`. Send the bearer header on the WebSocket upgrade to `/ws?orchestrationProtocol=2`, then Effect JSON RPC:

```json
{"_tag":"Request","id":"1","tag":"orchestration.dispatchCommand","payload":{"type":"thread.metadata.update","commandId":"<unique-id>","threadId":"<t3-id>","title":"<Session Title>"},"headers":[]}
```

Only a correlated `Exit` with `exit._tag:Success` and a non-negative `exit.value.sequence` acknowledges dispatch. Handle batched frames; cap frame/message sizes and waits. Auth, upgrade, rejection, malformed success and connection failures are explicit. Rejection diagnostics include only failure `_tag`/`code`, never trace IDs or arbitrary error content. Titles are trimmed before dispatch. HTTPS origins remain supported with bundled webpki roots, matching the HTTP client; neither transport depends on Linux certificate directories. Preserve ownership checks and pending-journal recovery. Dry-run does not discover auth or open a connection. Never write native projection rows or issue credentials.
