# T3 orchestration v2 is the sole live Thread authority

T3 left `state.sqlite` and its old Thread projections intact after switching to `statev2.sqlite`; reading them produced successful empty incremental exports while new Threads accumulated elsewhere. Read only the v2 Thread tables, validate the required capture schema before enumeration, and fail with the missing table/column instead of falling back. Project rows and Project events still use their unprefixed tables inside the v2 database. Historical Capture decoding remains necessary for reconstruction; it does not consult a legacy Store.

A root Provider Thread's strong native reference proves Session identity; a shared provider-session process does not. Keep every exact root identity fact and refuse ambiguous recovery rather than assign one mixed Thread transcript to an arbitrarily selected provider Session. Capture native-child and delegated Subagent rows verbatim; canonical parent links still require the Source's proven relation semantics.

Superseding the T3 transport portion of ADR-0006: the installed v2 build removed HTTP command dispatch. Title Write-back uses authenticated Effect JSON RPC `orchestration.dispatchCommand` over `/ws?orchestrationProtocol=2`, command `thread.metadata.update`, and a correlated successful Exit with a non-negative sequence. Existing paired bearer credentials only; never issue credentials or mutate a projection/database directly. Explicit upgrade/protocol/rejection errors preserve the pending ownership journal. Fixture servers verify dispatch; native live writes require a separate operator action.

V2 import drops legacy runtime/activity clocks: thirteen copied production Captures had higher timestamps than their authoritative v2 imports. Order by storage generation before native revision, using the fixed Adapter revision-3 format boundary in sidecars and projection rows. A generation advance retains the legacy body/Provenance as a Prior Revision; a generation downgrade is refused, and native timestamp rollback still fails within v2. Apply this ordering to local Capture, Bundle ingest and global Orchestrator election without a database migration or live legacy reads.

Imported shells are a documented exception to the new-provider identity path: capture the v2 import ledger, and use only the latest same-Host/Thread legacy Prior Revision for exact identity and recovery Dialog when no root Provider Thread exists. Retention and extraction are shared by local Pull, central Bundle settlement and Rebuild. Do not query frozen live runtime rows: retaining their original captured evidence avoids another native schema dependency. A present v2 root reference suppresses inheritance, including malformed references. Prior Revisions remain preserved historical bodies, not separately elected projections.
