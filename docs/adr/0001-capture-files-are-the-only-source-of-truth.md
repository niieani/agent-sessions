# Capture files are the only source of truth; SQLite is a rebuildable projection

**Extended 2026-09-04:** [Project Assignments](2026-09-04-project-assignments-are-durable-files.md) add durable classification files; SQLite remains reconstructible. The original decision below records its earlier scope.

The archive has two layers with opposite change rates. Captures — each session's native payload, preserved verbatim as a zstd-compressed file per session — are the only irreplaceable data. Conversations, indexes, bookmarks, and search live in a single SQLite file that can be fully regenerated from the captures (`rebuild` = re-extract everything). We chose this because agent vendors evolve their formats rapidly: a wide "lossless canonical schema" would need a migration every time a vendor adds an event type, while verbatim capture costs zero code to keep new data and a deliberately narrow Conversation schema (user messages, assistant responses, subagent links) stays stable for years. It also gives the best durability story: the only thing that must never be lost is a directory of dumb compressed files — greppable, rsyncable, readable decades from now — while the queryable database is disposable cache.

## Considered Options

- **Wide lossless canonical schema, versioned + migrated** — rejected: permanent schema treadmill driven by vendor churn.
- **Everything in SQLite, captures as blobs** — rejected: makes the database irreplaceable, so its integrity and backup become critical instead of incidental.
- **Postgres / Turso / any server** — rejected: the archive must not require running a service.

## Consequences

- Extraction is re-runnable: adapter bugs are fixed by re-extracting old captures, never by re-reading (possibly vanished) native stores.
- Actions (tool calls, parameters, results) are deliberately absent from the Conversation schema; they are recovered from captures on demand.
- For SQLite-backed sources (Cursor, VS Code), a capture is the per-session JSON blobs extracted from the store, not a copy of the whole database.
- Digests are the one other durable layer (ADR-0005): paid-for model output stored as files beside Captures, never regenerated by `rebuild`.
