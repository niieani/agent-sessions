# Agent Sessions — Specification

**This is a living document.** It is the canonical description of what this product is, why it exists, and what it must do. It evolves with the product: any change to features, behavior, or scope must be reflected here in the same change. Vocabulary is defined in [CONTEXT.md](./CONTEXT.md) — terms capitalized here (Session, Capture, Conversation, …) mean exactly what the glossary says. Hard-to-reverse decisions live in [docs/adr/](./docs/adr/).

**Delivery status:** Implemented contracts are documented below; [PLAN](docs/PLAN.md) tracks remaining work and [completed slices](docs/PLAN-completed.md) record implementation evidence.

## Purpose

Create a durable history of the conversations a user has with AI coding agents — regardless of which tool was used, across every machine they work on, outliving any individual tool's storage.

## Why this exists

- **Native stores are ephemeral.** Agent tools rotate logs, prune databases, and get uninstalled. Cursor's history is one vacuum away from gone; a reformatted laptop takes its sessions with it.
- **The conversation is the value.** What the user asked and what the agent answered is ~90% of what anyone ever needs later. The agent's actions (tool calls, parameters, result payloads) are noise in a transcript and are recoverable from raw data when needed.
- **Vendors churn formats.** New event types appear constantly. The archive must absorb them at zero cost, not require a schema migration or tool release per vendor change.

## What matters, in order

Extraction and rendering follow a strict importance hierarchy:

1. The user's messages.
2. Agent Messages: task instructions delivered into an agent-created Session by another agent.
3. The assistant's responses (the user references their contents later).
4. Subagent responses, linked by reference from the main Conversation.

Excluded from Conversations and Transcripts by default, recoverable from Captures on demand:

5. Which tools were called and with what parameters.
6. Tool call status (succeeded/failed).
7. Full tool result payloads (e.g. a `cat README.md` result — pure noise in a transcript).

Simplification is therefore a core function of the product, not a cosmetic afterthought.

## Requirements

### Functional

- **Sources**: agent Sources are Claude Code (`~/.claude/projects`), Codex (`~/.codex/sessions`), Cursor (`state.vscdb`), VS Code / Insiders (`workspaceStorage`), and Pi (`~/.pi/agent/sessions`). T3 Code (`~/.t3/userdata/statev2.sqlite`) is an Orchestrator Source: it contributes Augmentations to exactly linked agent Sessions, never duplicate Conversations. One Adapter per Source; Adapters are the only code that sees native formats.
- **Repository Resolution**: Capture metadata preserves a separate optional `repositoryResolution` fact (recorded path, lookup outcome, unresolved flag), never altering the verbatim native payload or native Git snapshot. Normal Pull backfills archived Sessions from indexed per-Host workspace, branch, recorded URL and Native Project facts, including SSH Hosts after the version/deploy handshake. It never re-extracts Session Captures for repository lookup; Rebuild indexes each fact while it already visits that Capture. A settled lookup is reused until its Capture revision changes, including negative Path and Missing results. Missing results still consume later indexed T3 evidence without another directory lookup. Pending paths are batched into SSH repository commands per Host, with independent per-path results. Each complete shell-quoted command is limited to 100 KiB, including JSON escaping and UTF-8 bytes; larger path lists use multiple batches, and a single oversized path reports its own error while other paths continue. Git `origin` lookup is Source-independent. Missing directories may resolve through exact T3 provider Links and already-captured Project repository identity (origin canonical key first, then the canonical key), or lookup of the captured Project workspace root on that Host. Successful host/path answers are sticky and reusable. Lookup execution errors are warned and retried, never recorded as negative answers. Git runs in a separate process group with a 15-second deadline per path, shared by both Git commands; expiry kills the group and reaps the child. Recorded working paths are never probed by in-process filesystem calls or child setup: Git and the negative-discovery access probe touch them only after exec. Because Git may report denied metadata as "not a git repository", Path is recorded only after a bounded shell probe confirms no .git entry at the physical workspace or its ancestors. Existing or inaccessible .git entries, explicit EPERM/EACCES diagnostics, and ambiguous probe failures are retry-later. Lookup work has a two-minute aggregate budget per Host Pull, including all local paths or remote batches; paths not reached are deferred. Fleet exports defer lookup until all Sources have been ingested, so this budget is shared across Sources. Each SSH repository batch has both a remote budget and a local process-group deadline within the remaining Host budget, preventing a stalled remote from blocking Pull indefinitely. The per-Host summary reports distinct retry-later paths and a sample path; execution errors, timeouts, and budget deferrals do not make Pull fail. Existing facts (including negative observations from earlier Capture revisions) and placement survive a deferred lookup; failed revisions remain eligible on the next Pull. Under macOS launchd, removable-volume permission prompts may prevent new paths from resolving. These retain their previous placement or path Project until a shell Pull resolves them, unless a captured T3 Link or Name Table supplies identity. A timeout alone never establishes Missing or unresolved status. Rebuild reconstructs the separate SQLite index from Captures without Git or SSH. All Capture writers and identity-based readers share the Adapter-owned Capture path policy: SQLite identities use bounded encoded stems, file Sources preserve their native hierarchy, and branch Sessions resolve to their base Capture. Repository refresh path/open failures are isolated per unit. Operational disk and database errors remain explicit in a separate per-Host repository-resolution report; they never replace completed Source statistics. Pull exits nonzero for repository refresh unit or operational failures while retaining the collected Host/Source counts; retry-later lookup deferrals remain nonfatal.
- **Capture birth-time evidence**: file-backed Capture sidecars record `nativeBirthTimeMs` from std's `metadata.created()` on macOS and the `statx` syscall requesting `STATX_BTIME` on Linux (including static musl). Linux requires the returned `stx_mask` birth-time bit; a missing bit or unavailable syscall records explicit null, while other IO errors fail. Capture queries the opened inode, not a potentially replaced path. Codex aggregate Captures record each segment's `birthTimeMs` and the minimum only when all segment birth times are known; SQLite unit Captures have no per-Session native birth time. Full Pull refreshes this evidence even for unchanged bodies; local incremental enumeration also compares birth time, so a replaced inode with preserved bytes/mtime is rechecked. Bundle settlement merges the latest birth observation separately from body election. Historical sidecars missing evidence require `pull --full-source claude` on the fleet for a complete backfill; rebuild never stats native Stores.
- **Capture admission and native copies**: `[pull] exclude-paths` (default `[]`) excludes recorded Session working paths, falling back to the native project directory when absent. Uses Kind path glob semantics, including home expansion; applies before Capture and indexing locally and in SSH Export. Admission reads only recorded native metadata, never Capture or Extract: Claude/Pi recorded cwd, Codex first session header cwd, T3 recorded worktree, and no working path for ChatGPT/Cursor. Rebuild uses the same recorded fields from Captures. Admission errors fail only that Session identity, withhold its Source Bookmark and retry next Pull; busy admission remains retry-later. Excluded units contribute no failure/unchanged counts or Bookmark. Elect one same-Host Source/native-ID copy by lexicographically smallest absolute eligible native path before Bookmark filtering, independent of mtime/size; location does not change Session identity. Genuine winner divergence still revises; identical retained bodies do not create another Prior Revision. Policy changes rebuild the derived index once during Pull; Rebuild skips matching archived Captures and their Bookmark contribution. Existing Captures, Prior Revisions and Digests stay on disk; removing exclusion restores archived evidence. No Digest freshness change or model calls. Kinds remain View policy and preserve admitted Captures regardless of claims. See [ADR](docs/adr/2026-11-07-capture-admission-and-native-copy-election.md).

- **Concurrent native writes**: file-backed and Codex aggregate Capture re-open and re-stream up to three times, with 50 ms between attempts, when post-stream size or mtime proves a concurrent native write. Exhaustion is counted as `retry-later`, warned with Session identity on every Pull, and exits 0 unless another failure occurs. Prior Capture files and the Source Bookmark remain intact; staged bytes are removed on all exits. Busy admission probes withhold their entire Session identity from copy election and count as retry-later, without admitting an unverified Capture. Remote Bundles carry a default-zero `unitsRetryLater` count and withhold Bookmark advancement too. There is no age-based escalation: active agents can legitimately keep writing indefinitely; every deferral remains visible, and all other read/stat/compression/parse/archive errors still fail.
- **Capture**: preserve each native archival unit's payload verbatim (zstd-compressed, one file per Session or Orchestrator Thread). New native event types must cost zero code to keep. For SQLite-backed Sources, the Capture is deterministic typed NDJSON of the unit's raw rows and referenced attachment bodies, not a database copy.
- **Extract**: produce the canonical Conversation (tiers 1–3) from an agent Capture, or an Orchestrator Thread projection and Link fact from an Orchestrator Capture. Extraction is re-runnable over old Captures at any time; improving an Adapter never requires re-reading a native Store.
- **Source-specific extraction policy** (Capture is never affected — every admitted native archival unit is preserved; these rules govern the projection extracted from it):
  - *Claude*: ordinary `type:"user"` and `type:"assistant"` records supply Dialog after the documented noise filters. A `type:"attachment"` record with `attachment.type:"queued_command"` and `attachment.commandMode:"prompt"` is also a real user Message: extract its string/text-block prompt at the attachment's native position and timestamp. `commandMode:"task-notification"` remains machine plumbing. Never assume queue drain creates an ordinary user copy, and never text-deduplicate identical prompts without an exact native correlation join. The regression and raw shapes are pinned in [docs/formats/claude.md](./docs/formats/claude.md#queued-user-prompts).
  - *Codex*: the Store spans both `~/.codex/sessions` (date-partitioned `YYYY/MM/DD`) and `~/.codex/archived_sessions` (the vendor *moves* files there when a thread is archived — both trees are enumerated; the Archive never mirrors the move as a deletion, and a move in either direction with unchanged bytes keeps the Capture body — only the sidecar's recorded native location (`nativePath`, each rollover segment's path) is updated, reported as unchanged, so the next enumerate skips it again). **Guardian sessions** and ordinary **subagent-flagged sessions** are Captured but currently yield no Conversation: guardian "dialog" is machine-generated review prompting, while ordinary child files replay parent history and the current format census provides no proven general boundary between replay and child-owned exchange. They remain preserved until that boundary can be extracted without guessing. Injected context arriving as `role:"user"` (`<environment_context>`, `<skill>`, `<user_shell_command>`, `<codex_delegation>`, `<external_codex_apps_open_page>`, `<hook_prompt …>`, and `<heartbeat>`) is dropped at Extract; unknown leading tags retain their text and warn, so a new vendor envelope cannot silently erase user input. `<send_user_message_question_reply>` JSON arrays become user Dialog containing every question and answer (malformed bodies survive verbatim with a warning); UI mirrors and compacted histories remain ignored. `<turn_aborted>` markers are kept (real dialog context); `<subagent_notification>` spans are stripped with surrounding user text surviving. A Composer Prompt (context sections, then a `## My request for Codex:` or `## My request:` heading, then the typed request) keeps only the typed request when every section is Machine Context — attachment and application labels, `source="ambient-ui-state"` elements, in-app browser, Chrome tab and IDE state; sections the user chose (selected text, response annotations, referenced chats) keep the part verbatim, as does any layout not recognized, and a Message whose only content is Machine Context keeps it rather than being dropped ([docs/formats/codex.md](./docs/formats/codex.md#composer-prompts)). Goal envelopes (`<codex_internal_context source="goal">`) are the exception: retain only their user-provided `<objective>` or `<untrusted_objective>` as a typed user Goal Message, discard the runtime continuation/budget/audit instructions, and project an unchanged repeated objective as a typed Goal Continuation. A changed objective always emits a new Goal, including a later return to an earlier value. Goal-objective file references may resolve only from a Capture-owned snapshot made on the Source Host; Extract and Render never read live attachments. Messages extract from the `response_item` stream only (`event_msg` records are UI-facing duplicates), except the `event_msg` `agent_message` fallback for degenerate old files with zero assistant `response_item` messages; The native title is `threads.name` in `<codex-root>/state_5.sqlite` (the user-visible `/rename` name, read in a read-only transaction; `threads.title` is the raw first message and is never used); the `thread_name_updated` JSONL event is a fallback only for rollouts absent from the sqlite catalog — Codex stopped emitting it around 2026-05 (latest wins within a source; catalog row presence wins across sources even when its name is null or empty).
    - The sole function-result exception is an initial `function_call_output` in a `thread_source:"agent_created_thread"` Session: only a `codex_app.create_thread` result containing a well-formed `codex_delegation` with nonempty `source_thread_id` and `input` becomes an Agent Message. It may follow only omitted injected `message` context, and remains the first projected Message. It never becomes a user Message or Subagent Parent Instruction; every other function result remains an omitted Action.
  - *Pi*: since session v2 entries form a **tree** (`id`/`parentId`, in-place branching). The Conversation is the root→leaf path ending at the file's last entry — exactly what Pi itself would send to the model; abandoned branches stay recoverable in the Capture. Pre-v2 files (no entry ids) extract in file order. Thinking blocks and tool calls are Actions: omitted from the Conversation but counted for seam markers; `toolResult`, `custom`/`hookMessage`, and extension-injected entries are never Dialog; a user-run `!` shell command (`bashExecution`) counts as one omitted Action. The title is the latest `session_info` name, where an empty name *clears* it (upstream semantics).
  - *Cursor*: one Session is a `composerData:<composerId>` row plus its optional `composerHeaders` row and every `bubbleId:<composerId>:*` row. Header order is authoritative when present; inline `conversation` is the legacy first fallback and a bubble-key scan is the last fallback. A Composer's native key is identity, never a Capture path: non-UUID keys use a deterministic path-safe Capture filename while the raw key remains in Provenance and the captured `composerData:` row. `type:1/2` maps to user/assistant; text falls back through `richText` (Lexical and TipTap trees) then legacy `markdown`; thinking-only bubbles are omitted and `toolFormerData` bubbles count as Actions. Cursor subagent composers are Captured and classified for global resolution but remain non-extractable until independent child Dialog can be proven. If an elected Capture changes from extractable to non-extractable, ingest keeps the Capture and retracts only that Host's projection; global election then either promotes another Host or removes the stale standalone Conversation.
  - *T3*: one native archival unit is one `orchestration_v2_projection_threads.thread_id` in `userdata/statev2.sqlite`. This is the sole live Thread authority; never fall back to frozen legacy tables/databases. Capture the v2 Thread event stream, current v2 projections (including Provider Threads, shared provider-session bindings, Runs, nodes, Subagents, context transfers and checkpoints), current Project row and its still-authoritative Project event stream, checkpoint diffs, and safe referenced attachments from one read-only WAL-aware transaction, per [docs/formats/t3.md](./docs/formats/t3.md). Missing required tables/columns fail the Source explicitly and withhold its Bookmark. Extract no standalone T3 Conversation. Resolve only strong `nativeThreadRef` identities from root Provider Threads: `driver:claudeAgent` → Claude `nativeId`, `driver:codex` → Codex `nativeId`; unsupported or malformed references stay unresolved. Preserve all root identity facts; multiple distinct identities remain ambiguous and cannot recover mixed Thread Dialog. Native child Provider Threads and T3 Subagent relations remain captured evidence, not guessed parent links. Old Captures remain rebuildable through their historical decoder, without any legacy live-store reads.
- **Subagents**: parent References and child Parent facts are extracted independently per Host, then globally resolved into bidirectional links by canonical Session identity. Re-ingesting one Host replaces only that Host's facts; resolution uses the child and parent facts from each Session's Projection winner, never a cross-Host mixture. During database-only migration, a Session with no populated winner may deterministically use all of its existing facts, whether schema-v2 anonymous or schema-v3 Host-named, preserving links and child classification without Store enumeration. Once a winner is populated, filtering becomes strictly winner-Host; named refresh removes obsolete anonymous facts for that exact identity. Source-native keys are matching evidence, never identity, with strict precedence: exact child native id, then tool-use id, then parent-scoped agent id; identical facts deduplicate before ambiguity is assessed. A child Parent fact elects its sole parent; competing parent-side References (for example, stale cloned Cursor composers) cannot create another edge. If no child Parent fact exists, conflicting exact parent-side References remain unresolved. Ambiguous parent-side metadata never cancels an otherwise proven child/parent edge; it is omitted. Resolved `<subagent>` link blocks are merged into the parent's native Message order by spawn timestamp: Messages are never reordered when timestamps regress, ties follow all tied Messages, and missing link times sort last. Generated names and types are forced onto one physical line so Source metadata cannot forge reserved Transcript tags. A linked or orphaned child with Dialog is rendered for recovery but excluded from Project/Loose indexes. Every user-role Message in a child Transcript is rendered as `<parent>` so delegated instructions are distinguishable; database roles and text remain unchanged.
- **Orchestrator Augmentation**: Orchestrator projections and Link facts persist independently per Host. A deterministic revision-first Projection winner supplies one Orchestrator Thread's current facts; stale Host projections never mix field-by-field. Global resolution uses only exact `(provider Source, provider native id)` evidence from that winner. Missing provider Sessions remain unresolved until later ingest; malformed/unsupported evidence is warned and preserved; no title/path/text/time heuristic is permitted. A resolved Link adds provenance-bearing T3 metadata and exact-id lookup to the underlying Session without changing Session identity, Source, Projection winner, Conversation, or native title. An exact Link can separately supply Repository Resolution for a missing workspace; that resolution may relocate generated Views. Several T3 Threads may link to one Session and render in deterministic order. One winning T3 Thread with conflicting provider identities is ambiguous and contributes no Augmentation. T3 projected Messages remain stored for fidelity audit and future exact joins; this version never silently inserts/deletes/reorders agent Conversation Messages from cross-source text comparison. A resolved Link whose provider Session no Host has ever Captured yields a Recovered Session ([ADR-0007](./docs/adr/0007-recovered-sessions-from-orchestrator-dialog.md)): provider identity, Dialog from the Thread's projected Messages, `recovered_via` provenance; a later real Capture supersedes it and the Thread returns to Augmentation only.
- **Ingest**: incremental via per-(Host, Source) Bookmarks; idempotent — re-ingesting anything is safe. When several Hosts carry the same canonical (Source, native id), the regenerable database records every Host's extracted projection and revision, then elects one Projection winner: append-oriented file Sources prefer larger body size before mtime; logical SQLite Sources (Cursor and T3) prefer newer logical revision before their exact discriminator; T3 first compares its storage generation (legacy Adapter revisions 1–2 versus v2 revisions 3+) because v2 imports omit old runtime/event clocks; a generation advance retains the old body as a Prior Revision, and generation downgrade is refused; native-metadata revision and Adapter version follow; exact ties use Host deterministically. Capture supersede policy settles the authoritative body before Extract, so each extracted Capture always replaces the same Host's stored projection even if a stale database revision claims to be newer; election then rematerializes canonical Session fields and Messages or Orchestrator facts from the current winning projection. `session_hosts` and Orchestrator projection rows preserve Provenance. Thus local pull, Bundle arrival, and sorted rebuild converge independently of ingest order or stale regenerable state. A Bookmark is the highest native revision ingested for that (Host, Source): payload/native-metadata mtime for file Sources and the documented logical revision for SQLite Sources. Enumerate skips a native unit only when it is at or below the Bookmark **and** the Archive holds its Capture sidecar recording the exact revision/discriminator — the Bookmark alone is not a safe local skip condition, because files/rows can arrive with preserved or backdated revisions. The Bookmark advances (monotonically, never backwards) only after the whole Source ingested successfully, so partial failures leave the window open and retry idempotently. A run that finds nothing new is a fast no-op. Native units that grew or changed since last ingest extend or replace their same-identity record: change is detected by comparing the native revision/discriminator against the Capture sidecar, and the authoritative Capture supersedes atomically (body before sidecar). An associated native-metadata appearance or revision is tracked independently; a metadata-only change atomically refreshes the Capture sidecar without recompressing the unchanged body, and old sidecars without revision fields self-upgrade on their next check. Append-oriented file Sources settle a changed body by the Dialog their Adapter parses out of the Capture and the staged incoming body (role, timestamp, and text per Message, plus the span's last activity), never by byte size ([ADR](./docs/adr/2026-09-28-supersede-by-dialog-coverage.md)): an incoming body whose Dialog covers the Capture's (the Capture's Messages are an ordered prefix and the span ends no earlier) supersedes it at any size; one that lost Dialog from the end (a strict Message prefix, or the same Messages with an earlier span end) is refused and the Capture stands, because vendors prune/rewind and Captures are truth ([ADR-0001](./docs/adr/0001-capture-files-are-the-only-source-of-truth.md)); one whose Dialog diverged supersedes it while the old body and its Provenance are kept as a Prior Revision at `<native-id>.revisions/<captured-at-ms>.<ext>.zst` + `<captured-at-ms>.revision.json` beside the Capture, which Enumerate, rebuild, and lookup never treat as a Capture. Either body failing to parse fails that Session and keeps the Capture; there is no size fallback. Refusals count as failed Sessions on both ingest paths; divergences are reported (`revised`) without failing. Logical SQLite Sources instead refuse a lower logical revision but accept a newer revision even when current projections shrink after a native revert/deletion. A native unit whose Capture already matches is reused but still re-extracted, so a lost database self-repairs on the next `pull`. Every CLI Pull, Rebuild, and Render holds one Archive-local exclusive advisory writer lock across its mutations; a second writer fails explicitly before Capture temp cleanup, Capture commit, database replacement, or View changes.
- **Bundle**: the self-contained unit a Host exports for pulling — a tar stream with `manifest.json` as its first entry (bundle schema version, Host, Source list, the `--since` Bookmark basis, native-unit count, export time), then per native archival unit its Provenance sidecar (whose Host and Source must match the manifest) immediately followed by its Capture body under `captures/<host>/<source>/…`. Sidecar-before-body lets the central side skip an unchanged payload before its bytes arrive; both sides stream (export writes to stdout, ingest reads any byte stream) with bounded memory and no temp files on the stream path. Bundle ingest applies the same supersede rules as local capture: unchanged Captures are reused (and still re-extracted, so the database self-repairs); a changed append-oriented body is staged beside the Capture and settled by Dialog coverage (supersede, revise with a retained Prior Revision, or refuse), committing atomically (body before sidecar). Logical SQLite Captures use their Source-specific revision-first supersede rule and may shrink at a newer revision. A newer native-metadata revision still merges into the retained sidecar after either an unchanged or refused body, preserving the retained body's revision/discriminator. Ingest derives all destination paths from the sidecars, never from tar entry names, so a corrupt Bundle cannot write outside `captures/`; the Bookmarks a Bundle justifies include native revisions and are advanced by the caller only after the whole transfer succeeded. The `export` command is the remote side: a full export can include every available Source, while an incremental export selects exactly one Source and its `--since` Bookmark; fleet `pull` runs one source-scoped export per distinct Bookmark. Export creates a temporary spool (deleted afterwards), requires and touches no Archive, and logs to stderr only — stdout is exactly the Bundle. On a stateless remote the skip gate is Bookmark-only (there are no sidecars to double-check against, per ADR-0002); the stricter sidecar+Bookmark gate still governs local pulls, and idempotent central ingest absorbs anything a preserved/backdated-revision edge case makes a remote re-send or a full export re-cover.
- **Origin Host attribution**: Projection winner selects Dialog independently of origin. Pull records each native file's birth time in its Capture sidecar, including on unchanged full-source replay. For multi-Host Sessions with all birth times known, the earliest birth confirms origin if the gap to the next earliest is at least 1,000 ms; proximity within 1,000 ms to the first extracted record is reported as corroboration, not required. Unknown birth times or a smaller gap cannot establish origin. Exact, unambiguous T3 Provider Thread identity from all current Host projections supplies secondary execution evidence; Claude children inherit their exact parent's T3 evidence. T3 facts are re-derived on every reconcile, never persisted as durable claims. A single evidenced, captured Host confirms origin; otherwise multi-Host Sessions remain ambiguous and retain their previous Host. A sole unevidenced Host is unverified. Small `host-attributions/<source>/<identity-component>.json` preference files store only the last selected Host, preserving ambiguous choices across rebuild; first ambiguous sighting uses the deterministic Projection winner. Birth evidence reconstructs definitive origin from Captures alone regardless of Pull order. Before ingestion, missing preference files are seeded from only the previous Host scalar in the current index; disposable evidence-report fields are not durable inputs. Rebuild never reads the old database, native Stores, or sync daemons. `pull --full-source SOURCE` backfills existing file-backed Captures; no audit/import step. `origins list` reports every multi-Host Session, per-Host birth times, T3 evidence, decision reason, start-time corroboration and confirmed Copy Hosts. Birth-time-preserving copy tools can leave genuinely ambiguous evidence; missing or tied times never manufacture certainty. Render exposes attributed `session.host`, independent `session.capture_host`, `session.host_attribution`, and confirmed `session.copy_hosts`; info distinguishes Capture Host and origin. Digests, Leads, Render, activity, and Daily/Work Recap inputs use one canonical Source/native identity regardless of Capture Host count. Backup includes preference files alongside Captures, Digests, Project Assignments, and Leads; birth evidence travels inside Captures. See [origin decision](docs/adr/2026-10-09-origin-host-is-independent-of-projection-winner.md) and [origin attribution decision](docs/adr/2026-10-09-origin-host-is-independent-of-projection-winner.md).
- **Fleet pull**: a `pull` command collects from configured SSH hosts ([ADR-0002](./docs/adr/0002-pull-over-ssh-stateless-remotes.md)): system `ssh`, self-deploying static binary, remote Export streams a Bundle over stdout, central side ingests. Remotes are stateless and know nothing of the central archive. **The central host's own Stores are pulled the same way — localhost is just another configured host (one code path), and which hosts to include is configuration.** The fleet is configured in `<archive>/config.toml` as `[[host]]` entries: `name` (the Provenance Host name and Bookmark key — stable; renaming it makes the archive treat the machine as a new Host), optional `ssh` (a destination for the system `ssh`, so `~/.ssh/config` aliases, ProxyJump, and agents work; absent = this machine, read directly), optional Store-root overrides (`claude-root`, `codex-root`, `pi-root`, `t3-root`; T3 names its base directory containing `userdata/state.sqlite`), optional `remote-bin`. With no `[[host]]` entries (including a config containing only View settings), `pull` synthesizes a single localhost entry. For ssh hosts, `pull` first probes in one round trip — `ssh <dest> 'uname -sm; <remote-bin> --version'` — for the remote's platform and its binary's version, which must print exactly what the central binary prints. On a version mismatch or absence it self-deploys only when the remote platform (OS and architecture from `uname -sm`) equals the platform of the central binary's build target triple: `mkdir -p`, `scp` of the running binary to the remote path convention `~/.agent-sessions/bin/agent-sessions` (relative to the remote home; overridable per host via `remote-bin`), `chmod +x`, then re-probe. A remote on any other platform is never written to: that Host fails with an error naming the release asset target it needs installed at `remote-bin` (`aarch64-apple-darwin` or `x86_64-unknown-linux-musl`) and stating that the central binary cannot self-deploy across platforms. Mixed-platform fleets therefore install each release on every remote before the central host. Each Source then exports with that Source's central Bookmark and the Bundle is ingested straight off ssh stdout; Bookmarks advance only after the transfer fully succeeded. All ssh/scp runs use BatchMode, so an unattended cron pull fails fast instead of hanging on a prompt. Per-host failures are isolated: a failing Host is logged and counted, every other Host still pulls, and `pull` exits nonzero at the end if any Host failed. An Unreachable Host — ssh exits 255 on the first probe with OpenSSH's `ssh: connect to host …` or `ssh: Could not resolve hostname …` diagnostic (timeout, refused, no route, host down, name resolution) — is not a failure: it is logged at WARN, reported as `unreachable` in the per-Host summary and counted in the final `pull complete` line, keeps its Bookmarks, and catches up on its next successful Pull. Every other failure (authentication or host-key rejection, a failed probe, deploy, export, or ingest, or a connection lost after first contact) stays a Host failure. The Unreachable Grace bounds silence: `[pull] unreachable-grace` (integer plus `ms`/`s`/`m`/`h`/`d`, default `7d`) is how long after its last successful Pull (every Source succeeded) an Unreachable Host is still skipped; beyond it the Host fails with an error naming it and the time since its last success. Optional `[[host]] unreachable-grace` overrides the global grace for that Host, with the same duration syntax; invalid durations are hard config-load errors. The per-Host unreachable report shows the effective grace. Host Pull Health (first tracking and last-success times) is durable in `<archive>/host-pulls.json`, with `host_pulls` in `archive.db` as its rebuildable index. Pull and Rebuild backfill existing database records without contacting Hosts; Rebuild restores health even when the database is absent. Back up this file alongside other durable Archive inputs. A Host with no recorded success is measured from when this Archive first tracked it. Rebuild never restarts a known Host’s grace window. Already lost historical health cannot be recovered from Captures. See [ADR](./docs/adr/2026-11-07-durable-host-pull-health.md), superseding the earlier disposable-state decision.
- **Views**: markdown Transcripts; per-Project and per-Loose-month `INDEX.md` indexes; manifests; full-text search over Conversations. All Views are regenerable and disposable. Classification is derived only while rendering and is configured as ordered, user-named Kinds in `<archive>/config.toml` (schema in "View Kind configuration" below): the first Kind whose conditions match claims a top-level Conversation together with its Subagent children (an orphaned child is evaluated directly) and applies its Treatments. A Conversation claimed by no Kind uses an exact path Name Table entry first, then its verified Native Project or recorded repository key, then Repository Resolution, then its full recorded working path. A workspace found missing with a recorded branch and no resolved repository is unresolved and Loose; a Session with none of these identities is also Loose. Manual Project Assignments override automatic classification. The original path is retained in every case. No path is intrinsically disqualified — a home directory, filesystem root, or temporary directory can be a legitimate Project. By default Views are namespaced as `views/projects/<project>/` and `views/loose/<YYYY-MM>/` (Layout config below can change paths and output root); Loose is never represented as a fake Project. Project display names use Name Tables, then the repository’s `repo` segment or path basename (`root` for a filesystem root); distinct repositories sharing a raw name get a deterministic short repository-key hash suffix; path-only Projects independently retain the full-path collision rule. Only Projects that render a raw name take part in these collisions: one named by a Name Table never forces a suffix on the raw name another Project keeps. Repository and path-only identities sharing a raw name do not create new cross-kind suffixes. Project names become directories on filesystems that may ignore case (APFS by default), so derived names are then reconciled ignoring case and Unicode normalization: a path-only name adopts the one repository spelling it matches (a path-only `Servers` joins repository Project `servers`); any other derived names differing only by case get the hash suffix, as does a derived name that matches an explicit name (Name Table value, Project Assignment, or Kind group directory) only by case. Explicit names are never rewritten; two explicit names differing only by case fail the Render. The same repository key across worktrees and Hosts is one Project; without a repository or an unresolved missing-workspace observation, the same full path recorded on multiple Hosts is one Project, and a Kind's output group merges every recorded path routed to it.
- **Transcript design**: Transcripts are read primarily by agents (LLMs), secondarily by humans. This dictates: unambiguous role delimiters that cannot collide with message content (tag-style blocks, not markdown headings — assistant messages contain headings; delimiters live alone at column 0, and any content line that would read as one — a bare opening/closing reserved tag (`user`, `assistant`, `parent`, `subagent`, `goal`, `goal-continuation`, `gap`) or a whole-line `<gap … />` marker — is escaped in the View with a leading `\`, leaving database content verbatim); token economy — no per-message timestamps, a terse `<gap … />` marker only at large gaps (≥ 3 hours) or Workday changes; a one-line "— N actions omitted —" seam where Actions were dropped, so references like "that test failure" stay resolvable (on by default); YAML frontmatter (id, source, host, project, projectPath, optional native title, createdAt, updatedAt, messageCount; plus `activityDays`, the sorted list of every Workday on which the Session saw Dialog; plus subagent, parentId, subagentName, subagentType, subagentDepth for children when known; plus a deterministically ordered `orchestrators` list for resolved Augmentations) so each file is self-describing for humans and tooling. Each Orchestrator entry carries at minimum source/thread id/Host and may carry its distinct title, Project/model/runtime, and turn summary; native strings are serialized safely and never replace Session fields. Message text is never promoted to a fallback title: repeating the opening user text adds no information because it is already present in the body. When the Source supplies no title, omit the frontmatter field and leave the index title cell empty. A Goal Message renders as `<user><goal>…</goal></user>`; an unavailable referenced objective begins with `<!-- note: objective file no longer available -->`; an unchanged repeated goal renders as `<user><goal-continuation /></user>`. Project and Loose-month indexes are the navigation entry points so an agent reads one small file instead of globbing. Transcript filenames are a pure function of archive content — by default `<UTC-first-message-time>.<8-hex-of-session-identity>.<source>.md` within the classified View directory — never order-dependent, so re-rendering is byte-stable; the default layout needs no collision suffixes, and templated layouts using Digest Locked Titles get the deterministic suffix rule in "Templates, Layout, and Name Tables". Transcript links use percent-encoded CommonMark destinations so cross-group paths containing spaces or parentheses remain valid. Sessions without Dialog are archived but not rendered.
- **Agent Message rendering**: `<agent>` is an additional reserved role delimiter. An Agent Message renders as `<agent>…</agent>` and otherwise follows ordinary Dialog escaping, timestamps, gaps, and action seams; it does not make a Session match a user-Message View condition.
- **Workdays**: a Workday is the Archive's unit of "a day of work", not a calendar day. It is defined by a local IANA timezone and a configurable day-start time (`[views] timezone`, `day-start` in `<archive>/config.toml`; defaults: the central host's local timezone and midnight). A timestamped user Message starts a turn and owns the Workday its timestamp falls into; following assistant Messages inherit that turn's Workday, including untimestamped assistants and assistants that cross the boundary. An untimestamped user Message ends attribution for its whole turn until a timestamped user Message establishes a new Workday. An assistant Message with no preceding attributable user Message (e.g. a Conversation's first Message) takes the Workday of its own timestamp. Workday assignment is a pure function of Dialog Message timestamps and config, applied identically by Render (`activityDays` frontmatter and `<gap workday="…" />` markers) and by activity queries. The `<gap … />` marker is self-closing and attribute-based: `duration` carries the true positive elapsed time when ≥ 3 hours, `workday` carries the new Workday date (`YYYY-MM-DD`) when it changes, and both may appear together. The `agent-sessions activity --archive DIR --day YYYY-MM-DD` command lists Sessions with Dialog on the given Workday, backed by a regenerable index on Message timestamps; it never reads Captures or Stores.
- **Agent Workdays**: an Agent Message follows the same turn and timestamp rule as a user Message. In particular, a timestamped Agent Message starts an attributable turn and an untimestamped one ends the current attribution; a following assistant Message inherits the Agent's Workday under the ordinary Workday rule.
- **Session Days**: `[views] unit = "session-day"` renders one file per Session per Workday; the default `unit = "session"` keeps one file per Session. A Session Day holds the turns whose user Message falls in that Workday plus the assistant Messages those turns own, so a long turn crossing day-start stays whole in the file that started it; re-rendering may grow an earlier day's file only through such inherited assistant Messages. Each Session Day file exposes the Session's facts plus `workday`, `ongoing`, previous/next Session Day references, and its Digest when one exists. A Session Day is **Ongoing** when its winning Capture shows trailing Actions after the last Message, or the last Message lies within 10 minutes of the sidecar's `capturedAtMs`; capture time is persisted in the regenerable database for this purpose and a later Capture that shows more clears the state. Opening a writable `archive.db` migrates in place: a database that predates `captured_at_ms` gains the column and backfills it from Capture sidecars, so `pull` and `render` do not require a full `rebuild`. `rebuild` remains the complete reconstruct-from-Captures path. A Workday with no Dialog for a Session produces no file.
- **Digests** ([ADR-0005](./docs/adr/0005-digests-are-a-durable-second-layer.md)): `agent-sessions digest --archive DIR [--day YYYY-MM-DD | --from YYYY-MM-DD --through YYYY-MM-DD] [--session SOURCE:NATIVE-ID [--force]] [--dry-run [--json] [--redo-warn-fraction F]]` writes one Digest per closed Session Day that has none or whose covered Message range or Dialog fingerprint no longer matches, then refreshes the Session-level Digest. Before publishing a new Day Digest or attempting a title refresh, `session-title.pending` durably records that Session title work remains. A failed refresh is a counted hard failure, preserves the previous Session Digest (or leaves it absent), and stays selected on the next normal run without regenerating fresh Day Digests. Successful Session Digest publication or explicit repair clears the marker. Existing Digests without a marker keep their upgrade freshness; historical accepted fallback titles are not automatically rewritten. Storage: `digests/<source>/<identity-component>/<workday>.json` and `session.json`; the bounded identity component uses the same UUID/hex/hash encoding as Capture filenames, so opaque native ids are never interpreted as paths. `rebuild` never touches these files. Gating: Omitted Sessions, Sessions claimed by a Kind with `digest = false`, Subagent Sessions, Sessions without Dialog, Ongoing Session Days, and the current Workday are skipped; Subagent Dialog never enters a parent's input. Model access is OpenAI Chat Completions with JSON-schema structured output against a configurable base URL — `[digest] base-url`, `model`, `api-key-env`, `concurrency`, `max-input-tokens`, `request-timeout`, `retries`, `progress-interval`, `[digest.extra-body]`, and `[digest.prompts]`; the key is read only from the named environment variable. A successful HTTP response with missing or null completion content is a Rejected Digest, preserving the response envelope as `raw`; it uses the same bounded retry budget as malformed or schema-invalid model output. Transport, authentication and configuration errors remain hard request failures. A response that fails parsing, schema, or validation is retried up to `retries` times (default 2) within the same run, with the validation error appended as a correction turn; every Rejected Digest is appended to `digests/<source>/<identity-component>/<workday>.rejected.jsonl` (`attemptedAtMs`, `kind`, `attempt`, `error`, `raw`) so failures stay debuggable, and only after the last attempt does the Session count as failed for the run. `[digest.prompts] day` and `session-title` replace the built-in prompt texts (placeholders `{classifications}` and `{summary_budget}`); the defaults live in `src/digest/prompts/`. Input per Session Day: its Transcript body, the Project display name, the Session's Topic and Intent, and the earlier Session Days' Digests in order, each shown by its facet (`priorDigests[].facet`, the stored title without the Topic; null for a Topic-only title) rather than its full title. The system prompt ends with a title rule that names the known Topic outright on later days, and on a first day tells the model to choose its Topic first; the rule holds under a configured `day` prompt too. The Intent in Context is the latest one recorded by an earlier Session Day's Digest; when none is recorded and the Session Day being digested is not the Session's first, Context adds `opening` — the first three user or Agent Messages of the Session's first Session Day (Goal Continuations excluded), each clipped to 1,000 characters — so the Intent comes from the user's own direction, not a later day's agent plan. Three strict request schemas state the Topic and Intent contracts; returned output is validated even if the backend ignores the schema: the first Digest generated for a Session requires `topic` and `intent` as non-empty strings (a later Workday may establish them when backfill starts mid-history); a continuation with a known Intent carries no `topic` field and a nullable `intent`, where null keeps the Intent and a string records a user restatement or change of direction; a continuation whose earlier Digests record no Intent (they predate it, or the Session Day being re-digested is the Session's first) carries no `topic` and requires `intent`. Each Session Day Digest stores the resolved `intent` in effect that day ([ADR](./docs/adr/2026-09-27-session-intent-is-stored-on-each-session-day-digest.md)) — the model's new Intent, else the carried one — so one Digest file tells a reader the Session's purpose without its siblings; Digests written before Intent existed have no `intent` field and remain valid. When the summary names unfinished work or a next step that is not the user's own plan for themselves, the prompt asks it to say who proposed it and who must act (an agent suggestion the user did not take up; a named person other than the user); the user's own plans stay unattributed. `title` is the day's facet only (`<what this day did>`). A facet that equals or begins with the Topic (the known one, or the one chosen in the same first-day output), compared word by word, case-insensitive, ignoring separators and punctuation, is a correctable rejection: it is retried with a correction naming the Topic like any rejected output, and once retries are exhausted the tool accepts it with the leading Topic stripped instead of failing. A day left with no facet has none. The tool composes the stored title as `<Topic> - <facet>`, or just `<Topic>` without a facet, removing a redundant leading Project name when a nonempty title remains. Identical titles for the same Project and Workday, including two Topic-only titles, resolve through Render's ordinary collision suffixes. Existing titles are never rewritten by this rule. Remaining output fields: `tldr` (null unless the summary exceeds about 120 words), `summary` (proportional to Dialog — about one point per user turn, merged when repetitive, bounded by a token budget derived from Dialog size), `classification` (closed list `build | fix | research | qa | test | write | plan | ops | automation`, primary first). The tool adds `lockedTitle` (the first `title` ever written for that Session Day, never changed by `digest`), covered Message indices, `truncated`, `model`, `promptVersion` and `promptSource` (provenance of the prompt contract that produced the file; a bump never makes an existing Digest stale — only a changed covered range or Dialog fingerprint does), `digestedAtMs`. Digest requires `digest.tokenizer`, a local HF model directory with `tokenizer.json` and a string `chat_template` in `tokenizer_config.json`; missing or invalid tokenizer/template files fail before model calls, with no heuristic fallback. In-process tokenization counts the rendered chat template, generation prefix, and configured `chat_template_kwargs`, using the same Messages as the HTTP request, including correction retries. `digest.tokenizer-prompt-format` defaults to `chat-template`; `omlx` also counts oMLX’s response-format schema prompt injection when grammar decoding is unavailable. Over `max-input-tokens`, the largest Messages are middle-truncated first with `[message middle truncated]`, keeping both ends and leaving short Messages whole; every complete candidate is re-tokenized after UTF-8-safe cuts and `truncated` is set. Session titles and corrections also hard-fail above the limit. Tokenizer configuration never changes Dialog fingerprints, prompt version, or Digest freshness; if fixed Context alone cannot fit, that Session is an explicit counted failure before any request. The Session-level Digest holds the immutable Topic, `title` (a short stable name seeded from the Topic — the prompt suggests two to six words such as `Module Picker` or `Example planning`; the tool enforces only non-empty and at most 80 characters — refreshed on each new Session Day), plus the record of pushed native titles. A Kind's `classification = [...]` Treatment pins classification without skipping the model. `--dry-run` is the pre-flight check before a scheduled run: it reports every selected Session Day with a measured input token count, then one line per Source and a final summary line `digest dry-run: 412 new · 37 redo (dialog changed 37) · 1180 fingerprints · ~3h10m at last run's pace (chatgpt 400/10, codex 12/27)`. Planned items are counted as Digest progress counts them (Session Days plus Session titles): **new** items have no Digest yet (a Session Day without a Day Digest, a Session title without `session.json`); **redo** items regenerate an existing Digest through the model, by reason — `range grew` (the day gained Messages), `range moved` (the day's Messages sit at other indices), `dialog changed` (same range, different Dialog fingerprint), `forced`, `title refresh` (an existing Session title follows its changed or new Session Days), `invalid title`; **fingerprints** are Fingerprint Backfills a live run would write with no model call. The parenthesis gives new/redo items per Source. The duration divides planned items by the whole-run average pace (settled items over `started_at`→`updated_at`) of the run recorded in `digest-status.json` when that run completed; when the file is missing, or records a run still running, failed, or with no settled items, the line says `no rate history (<reason>)` and shows the measured input tokens instead of a duration. An unreadable status file is an error. When regenerated Session Days (titles excluded) exceed the new Session Days, or exceed `--redo-warn-fraction` (default 0.05, 0 to 1) of the existing Day Digests of the selected Workdays, it prints a `WARN:` line on stderr explaining that a release may be invalidating existing Digests; the warning never changes the exit status. `--json` prints the same summary as one JSON object instead of the text (`new`, `new_days`, `new_titles`, `redo`, `redo_days`, `redo_reasons`, `fingerprints`, `existing_day_digests`, `input_tokens`, the same fields per Source under `sources`, `estimate` with `basis` `last_run` | `token_count`, `items`, `duration_seconds`, and either `rate_per_hour` and `run` or `reason`, then `redo_warn_fraction` and `warning`). A dry-run opens the database read-only, takes neither the Archive writer lock nor the Digest status lock, writes nothing, and is safe beside a running digest; unknown outputs and prior Digests are not invented for the estimate. `retitle --archive DIR [<native-id> [--day D]] [--dry-run] [--json]` is the only operation that replaces a drifted Locked Title with its current Digest title; it plans the complete collision-aware Transcript and descendant-Subagent old→new path set for an external link-aware consumer, writes only selected Digest files in live mode, and never mutates Views.
- **Templates, Layout, and Name Tables**: Render uses [minijinja](https://github.com/mitsuhiko/minijinja) templates with `trim_blocks` and `lstrip_blocks` enabled and the trailing newline kept, so `{% if %}`/`{% for %}` lines leave no blank lines behind; the `yaml` filter turns any string into a safe plain or quoted YAML scalar, and templates never need block scalars. `[views] template` names a user file rendering Session, Session Day, and Subagent files; `index-template` renders indexes; absent keys use built-in templates that reproduce today's Transcript and `INDEX.md` byte for byte. The data model exposes every Session, Session Day, Digest (including the Session Day's `intent`, null for Digests that predate Intent), Subagent, Orchestrator, and Workday fact, the mapped display names, and a pre-rendered `body` (the escaped pseudo-XML Dialog with gap markers, action seams, and subagent link blocks) so templates never re-implement escaping. `[views] output` sets the View root (default `<archive>/views`); `[views.layout]` holds path templates `session`, `loose`, `subagent`, `project-index`, `loose-index`, and `json`, each relative to `output`; an absent index or json key produces none, and `subagent` may reference `parent_dir` and `parent_stem`. Filenames from templates that use a Locked Title remain a pure function of archive content (Captures, Digests, and Project Assignments, under the configured Layout); two units resolving to the same path get ` (2)`, ` (3)` suffixes ordered by Session start, so an earlier file never changes because a later one appeared. Units whose file names in one directory differ only by case (after NFC) would be one file on a case-insensitive filesystem; through the Project-name collision-safe rule, every such variant — including exact duplicates of a variant — gets its Session's `short_id` as `<stem>@<short_id>`, so which file is renamed never depends on Session order and names with no case variant are unchanged; exact duplicates left after that take the numbered suffixes. JSON Views follow the same rules. A unit whose layout references a Digest variable renders only once its Digest exists. A resolved Subagent waits until its parent View unit has a path, even when the Subagent layout itself is title-independent; truly orphaned children retain recovery rendering. `[views.source-names]`, `[views.host-names]`, and `[views.project-names]` map raw values to display names; templates alone decide link syntax. A Project Name Table key is an absolute recorded path, kept verbatim, or anything that normalizes to a repository key (`owner/repo` or a remote URL such as `https://github.com/owner/repo`); any other key fails config load. `[views] name-tables` lists Name Table files (relative paths resolve against the Archive root) — generated companions to `config.toml`, e.g. emitted from a notes system ([ADR](./docs/adr/2026-10-01-name-tables-load-from-generated-files.md)) — each holding optional `[source-names]`, `[host-names]`, and `[project-names]` tables and nothing else. Their entries merge with the inline tables; every key has exactly one origin, so a key defined both inline and in a file, in two files, or as two spellings of one repository fails config load naming both origins, as does a missing or malformed file. Project display precedence is exact recorded path key, then verified Native Project membership or a recorded repository key, then Repository Resolution, then the collision-safe raw path name. A directory found missing with a recorded branch but no resolved repository renders Loose, retains its recorded path, and exposes `session.project.unresolved` (the default Template writes `repositoryUnresolved: true` when the Session renders without a named Project; custom Templates must explicitly emit the marker using this field). Existing non-repository directories, repositories without `origin`, and missing directories without a recorded branch retain path Projects. Explicit Project Assignments still win. Render summaries report `unresolved_repositories` only for Sessions actually rendered Loose as unresolved; named or assigned Projects and skipped Sessions are excluded. Repository facts are loaded in bulk for rendering. Project relocation never invalidates Digests or changes Locked Titles; custom layouts using Project variables may rename stems as well as directories. Repository normalization removes scheme, user, host (including aliases), trailing slashes and `.git`; the last two path segments form `owner/repo`, including on non-GitHub hosts. Missing or malformed values (fewer than two segments, empty segments, traversal components, query/fragment or whitespace) use the path rule. Explicit Project Assignments override these names. Kind `match.path` still uses the recorded path. Render preserves bytes and mtimes for unchanged Views, reports actual changed files, and `render -v` lists written and swept paths to expose Project relocations. The `json` layout writes one pretty-printed, newline-terminated machine-readable file per rendered unit carrying the same data model, with object keys in stable lexical order. View filenames and directories use NFC Unicode normalization on every platform, applied to the complete rendered layout before collision assignment, manifest validation, navigation links, writes, or lookups; durable text and the configured output root are unchanged. Before writing, Render explicitly renames normalization-equivalent live entries to NFC, including directory components. It moves existing entries through a temporary sibling so APFS updates the stored spelling; unchanged bytes and mtimes are preserved, allowing git to detect content-identical renames. Existing distinct NFC/NFD entries claiming one live path are a hard error before any View mutation; Render never silently overwrites or deletes either. Orphan reconciliation keeps every normalization-equivalent live name regardless of inode identity. Case-only matches still require the same file, and kept case variants are respelled to the planned case; genuinely separate case variants on a sensitive filesystem are swept.
- **Title Write-back** ([ADR-0006](./docs/adr/0006-title-write-back-is-the-one-sanctioned-store-write.md)): `agent-sessions push-titles --archive DIR [--source S] [--dry-run]` pushes each Session's Session Title into its native Store's name field on the single configured local Host, per Source: Codex executes a guarded `UPDATE threads SET name` in `state_5.sqlite` only when `name` is null or equals the Pushed Name, or when `[titles.codex] overwrite-external = true` (default false; Codex auto-names every new thread, so External Names are the norm there and the opt-in is what makes write-back useful on Codex); Claude Code locks and rechecks the same open JSONL descriptor before appending a `custom-title` record, then publishes its prepared `custom-title.json` sidecar, only when no `custom-title` exists or its value equals the last value this tool pushed. Before native mutation the command writes a per-Session `push-title.pending` recovery journal beside `session.json`; Claude records its locked pre-append byte boundary there and inspects the suffix during recovery so a concurrent foreign title remains authoritative. Prepared sidecars must be regular files. After the Store and `session.json.pushed` agree it removes the journal. A repeated or crash-recovery run is a no-op at the native field. Dry-run opens the Archive database and Codex Store read-only, reads Claude JSONL without appending, prints pushes, unchanged titles, protected foreign titles, and missing Store records, and changes neither Store nor Digest. T3 Code reads `projection_threads` in a read-only WAL-aware transaction, resolves each local Orchestrator Thread through its Orchestrator Link (including Recovered Sessions), and dispatches `{ type: "thread.meta.update", commandId, threadId, title }` to the running server HTTP API. It never writes projections or uses offline execution. `[titles.t3] overwrite-external = true` has the same default-false Dispositions as Codex. Pushed Names use `session.json.pushed["t3:<thread-id>"]`; the shared per-Session journal identifies the Thread and is recovered before another mutation. Digest updates preserve other Threads’ Pushed Names. Dry-run needs no server; live dispatch discovers `userdata/server-runtime.json` and requires an existing paired bearer credential in `T3_BEARER_TOKEN`. Unreachable servers, missing credentials, and rejected commands fail explicitly per Thread. Setting the title clears pending T3 title regeneration server-side; Cursor is never written. No other command writes a Store.
- **Store Retention**: a Source's application may delete Sessions from its Store on its own schedule (Claude Code: `cleanupPeriodDays` in `~/.claude/settings.json`, default 30 days; see `docs/formats/claude.md`). Export reports each Source's Retention per Host in the fleet manifest when it can read it, and `pull` warns once per Host and Source when Retention is at most 30 days (including zero), naming the setting to change. This covers the default Claude deletion window and shorter windows that threaten collection after missed Pulls; longer retention, including 36,500 days, is silent at WARN. A change into the warning window is visible on the next Pull; `[pull] warn-store-retention = false` silences it. The Archive never compensates: a Session deleted before its first Capture is lost.
- **Resilience**: one bad native archival unit is warned and counted while later units and Sources continue; any failure withholds that Source's Bookmark. A separate retry sentinel is made durable before new/extended Capture commit or reused-Capture Extract/upsert, remains alongside valid Provenance, and is removed only after derived work succeeds; legacy inline `needsRetry` markers remain honored. File Capture re-stats its opened native file before and after streaming; SQLite Capture holds one consistent read transaction and re-stats referenced attachment files before/after streaming. Interrupted `.tmp` siblings are swept before ingest/rebuild. Bundle ingest rejects pair-count mismatches, duplicate identities, non-canonical Host/Source/native-id path components, and fleet manifests that do not echo the requested Host, Source, and Bookmark. A refused payload (lost Dialog, or a lower logical revision) counts as failed on local pull and Bundle ingest alike, so a stateless Host resends it; a Session whose Capture or incoming body cannot be parsed for the coverage check fails the same way and its Capture is never replaced. Archive writer guards explicitly unlock before closing their descriptors. A concurrent child spawn may inherit a CLOEXEC descriptor until exec; that inherited descriptor must not prolong a released writer guard. Concurrent live writers still fail immediately, without retries.
- **View purity**: Render validates every config, layout, path, template, and planned file before its first disposable View mutation. It refuses an output that contains the Archive, overlaps durable Archive data or a configured/local native Store, or is itself a symlink; canonicalizing an output's existing ancestors prevents an ancestor symlink from redirecting later writes. A successful Render reconciles file/directory topology changes, removes orphaned files and empty directories, and unlinks nested symlinks without following them. Planned file paths must be unique and cannot be each other's ancestors, including when compared ignoring case and Unicode normalization; two planned paths or directories that differ only in that way and remain after collision naming (for example case-variant directory components from a custom layout) fail the Render before any mutation. Gap markers report the true positive elapsed duration and ignore out-of-order timestamps.
- **Origin diagnostics**: WARN for a first ambiguous decision, a transition into ambiguity, any retained Host change, or exact T3 claims conflicting with each other or the elected Host. Repeated ambiguity with the same retained Host uses DEBUG; the attribution remains available through `origins list`.
- **CLI reporting**: `pull` emits one stable Host/Source row with found/new/extended/revised/unchanged/refused/retry-later/failed counts and elapsed time, then an aggregate outcome. `-v`/`-vv` and `-q`/`-qq` tune stderr diagnostics while `RUST_LOG` takes precedence. Export stdout remains exactly its Bundle. Successful changed and no-op runs exit 0; any partial/fatal failure exits 1; clap usage errors exit 2.
- **Rebuild**: regenerate the entire database (Conversations, Orchestrator projections/Links/Augmentations, indexes, search) from Captures and durable Project Assignment files, restoring any Digest cache from Digest files — drop `archive.db`, re-extract every Capture via its Provenance sidecar, never touching a native Store. Bookmarks are restored from sidecars' recorded native revisions, so the next `pull` stays incremental. Resolution runs after every relevant Source projection is restored, independent of Capture traversal order. The result is content-equivalent to the database it replaces, and re-rendered Views are byte-identical (rendering is deterministic — a pure function of archive content and configuration). Captures whose Source has no Adapter yet are preserved and skipped, never lost. Rebuild never renders or mutates the configured View output; invoke Render explicitly under any caller-owned output lock. The Archive-local lock does not replace that external lock.

- **Digest maintenance**: `digest --archive DIR --list-omitted` lists existing Digest directories whose Sessions the current Kinds omit; it opens the database read-only and never deletes. `--from YYYY-MM-DD --through YYYY-MM-DD` selects one inclusive Workday range for a bounded backfill invocation; both bounds are required and cannot be combined with `--day`. `--session SOURCE:NATIVE-ID` restricts candidates to one Session and fails explicitly when that Session has no Dialog, is a Subagent, or is not digested. `--session S --day D --force` regenerates Session Day D even when its Digest covers every Message — the way to re-digest after an extraction change leaves the covered range unchanged. The Session Day must be closed (not the current Workday, not Ongoing), and every earlier Session Day must have a Digest covering exactly its current Messages, because they supply the Topic, Intent, and prior Digests the forced day is written against; otherwise the run fails before any request, naming the earlier day to digest first. Force keeps the Topic and Locked Title, re-establishes or carries the Intent under the same schema rules as any continuation, refreshes the Session Title, and leaves later Session Days unchanged: re-digest them in order to carry a changed Intent forward. New day and Session Digest files record `promptSource` as `builtin` or `config` without changing `promptVersion`; `rebuild` ignores and preserves Rejected Digest sidecars.

- **Digest progress**: before any request, `digest` and `repair-digests` count their planned items — each selected Session Day plus each Session title the run will request — split by Source. Every item start and settlement atomically rewrites `<archive>/digest-status.json` (temporary file + rename): `schema_version`, `command` (`digest` | `repair-digests`), `pid`, `host`, `started_at`, `updated_at`, `state` (`planning` | `running` | `completed` | `failed`), `total`, `done` (settled items, successful or failed), `failed`, `rejected` (Rejected Digests), `sources.<source>.{total,done,failed}`, `current` (the most recently started in-flight item: `source`, `session`, `workday`, `kind` `day` | `title`), `in_flight`, `rate_per_hour`, `eta_seconds`, `eta_at`, `progress_interval_ms`, `error`. When a Session fails, its unsettled items settle as failed; a repair skipped as already completed settles them as done. Every `[digest] progress-interval` (default `"5m"`, must be positive) a reporter thread refreshes `updated_at` and logs at INFO `digest progress 412/1180 (35%) · chatgpt 2026-04-12 · failed 0 · rejected 3 · elapsed 21h40m · ETA 3h10m`; the ETA divides remaining items by the settlement rate over the last 30 minutes, and is unknown when nothing settled in that window. The run logs the planned totals at start and a final `finished` or `failed` line at the end, and leaves its final state in the file. A failed mid-run status write is logged as an error without stopping paid-for work; the initial and final writes fail the command. The writer holds an exclusive lock on `<archive>/.digest-status.lock` for its whole run (taken after the Archive writer lock). `digest status --archive DIR` reads the file and probes that lock without blocking — never the Archive writer lock — and reports the run as live, finished, starting (a new run holds the lock before its first write), or stale: `planning`/`running` while no process holds the lock means the writer died. It exits 1 for a stale or failed run and fails explicitly when no status file exists. `--dry-run` writes no status and logs no progress.

- **Explicit Digest repair**: `repair-digests --archive DIR --loose [--force] [--dry-run]` replaces each eligible Loose Session's complete settled Digest set, including Topic, Session Title, day titles and Locked Titles. It honors configured concurrency. `repair.completed` fingerprints Dialog and prompt context, including `promptVersion`, so unchanged successful repairs are skipped and the first repair after a prompt-version bump regenerates every eligible Loose Session; `--force` explicitly regenerates them. Generation failures preserve the old set, record `repair.failed`, and retain Rejected Digest sidecars. Successful generation publishes through `repair.pending`; normal Digest/Render readers refuse a pending set, and rerunning repair completes publication before making new requests. Title Write-back ownership and pending recovery state remain intact. `--dry-run` makes no model requests or durable changes. The mutually exclusive `--clean-project-prefixes` mode performs exact-prefix cleanup without model calls. Newly composed Day titles apply the same safe prefix removal; existing Locked Titles still change only through explicit maintenance.

### View Kind configuration

Workday settings live directly on `[views]`:

```toml
[views]
timezone = "America/Los_Angeles"   # IANA zone; default: the central host's local zone
day-start = "04:00"                # local time the Workday begins; default: "00:00"
```

Both keys are optional and validated at config load: an unknown timezone or a malformed `HH:MM` is a hard error before any View is touched. Changing either requires only `render` or an `activity` query — the Archive is never affected.

Kinds are declared as `[views.kind.<name>]` tables in `<archive>/config.toml`. The kebab-case `<name>` is the unit the user reasons about: it appears in diagnostics and the render summary. Document order is priority order — the first matching Kind claims the Session.

```toml
[views.kind.<name>]
match.<fact>.<op> = <value>   # conditions; alternatively repeated [[views.kind.<name>.match]] blocks
omit  = true                  # placement Treatment — exactly one of omit / loose / output
loose = true
output = "<group>[/<sub>…]"   # or "./<sub>[/…]"
digest = false                # Digest Treatment: never digest Sessions this Kind claims
classification = ["automation"]  # Digest Treatment: pin Classification; the model still summarizes
```

**Facts and operators.**

| fact | operators | matched against |
|---|---|---|
| `path` | `glob`, `is` | the recorded working path; a leading `~/` expands to the central rendering user's home |
| `message` | `is`, `starts-with`, `ends-with`, `contains`, `matches` | the first user Message of the Conversation, as an opaque string; later Messages (including continuation envelopes appended to the same Conversation) never affect the match |
| `source` | (bare key, no operator) | the Source name (`claude`, `codex`, `pi`, `cursor`, `vscode`) |

`matches` is Rust regex, unanchored. Message text is never interpreted (no YAML/JSON/Markdown/frontmatter parsing — that would leak one project's message protocol into the archive tool) and never normalized (no trimming or case folding). A Conversation with no user Message fails every `message` condition; that is not an error.

`source` means the Session's agent Source. A T3 Augmentation does not change it and `source = "t3"` is invalid because T3 produces no classifiable Conversation. A future Orchestrator-aware condition would be a separate additive fact family (for example `orchestrator.source`), not an overload of `source`.

**Composition.** Everything inside one match block is AND: multiple keys must all hold, and an array leaf means every element must hold (`match.message.contains = ["a", "b"]` requires both substrings). An array on an equality operator (`message.is`, `path.is`, `source`) can never hold and is a hard config error. OR is expressed as repeated `[[views.kind.<name>.match]]` blocks — the Kind claims a Session when any one block matches.

**Placement.** At most one placement Treatment per Kind; absent placement keeps the default Project/Loose classification:

- `omit` — Omitted: no Transcript, no index entry.
- `loose` — Loose: renders under `views/loose/<YYYY-MM>/`.
- `output = "name[/sub…]"` — a group folder under `views/projects/`, merging every recorded path routed there; `output = "./sub[/…]"` — a subfolder of the Session's own Project. Every output folder carries its own `INDEX.md`. Segments must be non-empty and never `.` or `..`; destinations are always author-typed literals — matched content never becomes a filesystem path.

**Digest Treatments.** `digest = false` and `classification = [...]` compose with `loose`, `output`, or default placement; combining either with `omit` is a config error (an Omitted Session is never digested anyway). `classification` values must come from the closed Classification list.

**Errors** — all hard, at config load, before any View is touched: an unknown key anywhere; a Kind with no match block, an empty match block, or multiple placement Treatments; an invalid glob or regex; an unknown Source name; a malformed output; a contradictory equality array.

**Observability.** The render summary counts claimed Sessions per Kind plus the unclaimed default; `render -v` lists each Session's id, claiming Kind, and destination. Changing Kinds requires only `render` — the sweep relocates or removes stale files.

**Examples.**

```toml
[views.kind.mechanical-capture]           # omit noise entirely
match.message.contains = "action: capture"
omit = true

[views.kind.example-assistant-eval]                  # gather scattered eval workspaces under one group
match.path.glob = "/work/example/Software/example-assistant/temp.local/eval-workspaces/**/vault"
output = "example-assistant-evals/automations"

[views.kind.scheduled-workflow]           # subfolder within the Session's normal Project
match.message.starts-with = "<workflow-marker>"
output = "./automations"

[views.kind.vault-backup]                 # AND: the path glob and both substrings must hold
match.path.glob = "/work/example/Vault/**"
match.message.contains = ["action: capture", "backup"]
omit = true

[views.kind.scratch]                      # OR: either match block claims the Session
loose = true

[[views.kind.scratch.match]]
path.glob = "~/Documents/Codex/*/*"

[[views.kind.scratch.match]]
path.glob = "/tmp/**"
```

**Extension policy.** The schema grows additively, never by reshaping:

- A new matchable fact is a new `match.<fact>.<op>` family (e.g. `host`, `created.before`, `duration.at-least`, `message-count.at-least`). Existing configs are untouched; an older binary rejects the unknown key loudly instead of mis-filing silently.
- A new Treatment is a new sibling key in the Kind body, stated once next to the condition it belongs to — e.g. future rendering configuration such as `render.assistant = "last-only"` or `render.roles = ["user"]`. Rendering Treatments compose with `loose`, `output`, or default placement; combining any of them with `omit` is a config error.
- `output` remains a plain string forever; related settings become sibling keys, never a promotion of `output` to a table (which would break existing configs).

### Dialog Statistics

Implemented in slice 27; decision: [ADR](docs/adr/2026-09-04-kind-matching-uses-current-dialog-statistics.md).

`match.dialog.<statistic>.<operator>` extends Kind matching. Statistics are `user-messages`, `agent-messages`, `assistant-messages`, `user-chars`, `agent-chars`, `assistant-chars`, and `total-chars`; operators are `eq`, `lt`, `lte`, `gt`, and `gte`, accepting nonnegative integers. Count non-empty extracted Messages per role; sum their text lengths in Unicode scalar values (not UTF-8 bytes), without trimming or normalization. `total-chars` is the sum of all role totals. Empty Conversations have zero totals. Actions, generated Digests, and other Sessions' Subagent Dialog are excluded.

Facts cover the complete current Conversation, even when Digest or Render selects one Workday. AND/OR composition, first matching Kind, and inherited parent claims remain unchanged. Unknown statistics/operators, non-integer or negative values, and contradictory numeric bounds are configuration errors. These predicates neither change the definition of Dialog nor introduce a separate eligibility gate.

```toml
[views.kind.no-response]
match.dialog.assistant-messages.eq = 0
omit = true

[views.kind.tiny]
match.dialog.total-chars.lte = 50
omit = true
```

Digest and Render share evaluation against the latest extracted Conversation, including after growth, re-extraction, or rebuild. Ingest preserves Omitted Sessions normally; no exclusion is sticky. A Session crossing the configured threshold becomes eligible on the next evaluation, subject to ordinary Digest gates. A short Session Day inside a larger Conversation is not independently omitted. Existing Digests survive omission; ordinary freshness checks apply when the Session qualifies again. Diagnostics report the claiming Kind and matching statistics without requiring a model call.

### Project Assignments

Implemented in slices 28–29; decision: [ADR](docs/adr/2026-09-04-project-assignments-are-durable-files.md).

`project assign <source>:<native-id> --project <name> --archive DIR` records one Project Assignment; `project unassign <source>:<native-id> --archive DIR` removes that explicit association. Validate the Session identity and a nonempty project name; unknown Sessions are explicit errors. No native Store or Capture is changed. Use a plain project reference, not Vault wikilink syntax. Per-Session files live at `assignments/<source>/<identity-component>.json`, with a versioned record containing exact Source/native identity, project reference, assignment timestamp, and optional reason. Use the existing bounded identity-component encoding. Publish complete files atomically, then refresh the database index; interruption cannot make SQLite the sole copy. Rebuild restores assignments; malformed records fail explicitly rather than silently dropping relationships.

Digest and Render use one resolved Project context: explicit assignment, then Project Name Table precedence (recorded path, Source-qualified Native Project identity, repository key), then Native Project, repository, or recorded workspace grouping, otherwise no Project (`null`). A Loose treatment suppresses incidental workspace-derived names; an explicit assignment overrides Loose placement. Omitted remains authoritative, and other Kind treatments (including explicit output routing, Digest gating, and Classification) remain effective. Path predicates continue to inspect the original recorded path. Explicit assignment on a Subagent wins over inherited project context; otherwise it inherits its parent's resolved Project. Relationships and hierarchy remain unchanged.

Assignments affect all Session Days, survive later Captures and rebuild, and are reversed by unassigning rather than editing generated files. An assignment does not itself regenerate paid-for Digests or rewrite Locked Titles. Project Name Tables remain reusable path, Native Project identity, or repository mappings; Session assignments remain individual associations. Backup includes `captures/`, `media/`, `digests/`, `assignments/`, and `config.toml`. Native Conversation reconstruction still depends on Captures, not classifications.

### Transcript relationships and title context

Project resolution, hierarchy, title repair, and Vault batch acceptance are complete (slices 29–32); see the [Digest decision](docs/adr/0005-digests-are-a-durable-second-layer.md). Vault-specific properties and naming live in its owned Template/Layout; the archive exposes source-neutral facts and resolved references.

- Session Day context adds a one-based chronological day index and a reference to the first Session Day. Indexing uses the complete Session's attributable Workdays, independent of a selected render range or Digest availability. References use collision-resolved paths; never link to a nonexistent target or substitute a later day for the actual first day.
- Subagent context adds a resolved parent Session Day reference using the parent turn's Workday at spawn time, plus parent identity and available name/type/depth. If spawn timing cannot establish the day, expose that absence explicitly; existing recovery placement is not proof of spawn timing. Nested Subagents link to their immediate parent.
- Vault notes share available session identity, source, host, Workday, project, model, Git/file metadata, and `update-policy: generated`. Subagents stay Untagged and agent-authored, carry `session-subagent: true` and `session-parent-id`; do not invent missing facts or list the operator as their participant. Session Days carry `session-day-index` independently of subagent status.
- A top-level continuation's `up` links to its first Session Day; the first day has no self-link. A Subagent's `up` links to the parent Session Day that spawned it, including when the Subagent spans days. Existing previous/next body navigation remains. No general `prev`/`next` properties are introduced.
- Digest input uses the same resolved Project as Render. Projectless Loose Sessions receive JSON `project: null`, never a temporary directory basename or the label “Loose” as a project. Topic and facet instructions prohibit redundant project prefixes and derive projectless Topics from Dialog. Session-title generation receives the same project context.
- Vault Project filenames become `<workday> <Project> - <Locked Title>.md`; Loose filenames remain `<workday> <Locked Title>.md`. Existing duplicate prefixes are cleaned explicitly: case-insensitive exact project-name match at a word boundary, trim leading whitespace/separators from the remainder, require a nonempty result, and do not fuzzy-match or damage meaningful punctuation. Repeated Render alone never mutates a Locked Title.
- The initial repair redoes all Loose Digests with corrected context, replacing Topic, Session Title, day titles, and Locked Titles coherently. Retain independent Title Write-back ownership/recovery records. Project assignment alone does not trigger this repair. This newly generated Vault batch has no external references, as confirmed by its owner; it can be regenerated directly without a separate rename plan. That exception does not remove the existing link-aware Retitle contract for later referenced notes.

View names must be accepted by Windows and by Obsidian Sync on every platform, and be addressable by Obsidian wikilinks. Layout scalar variables (`title`, `project`, `parent_stem`, `default_stem`, `source`, `short_id`, `workday`, `month`, `native_title`) represent filename components: Render replaces control characters with spaces, exact `.`/`..` values with fullwidth dots, and each of `/ \ : * ? " < > | # ^ [ ]` with its fullwidth lookalike (`／ ＼ ： ＊ ？ ＂ ＜ ＞ ｜ ＃ ＾ ［ ］`). Every component of a rendered layout path, and every Project directory name (derived, Name Table, or Project Assignment), then gets the same character mapping plus the position rules: trailing spaces are trimmed, trailing dots become `．`, and a Windows device name (`CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`, any case, with or without an extension) is spelled in fullwidth (`con.md` → `ｃｏｎ.md`); a blank component is a hard error, and a blank Project directory falls back to `Project`. The mapping is idempotent and runs before collision assignment, so names that become equal take the ordinary collision suffixes; Views spelled by an earlier release are removed by the orphan sweep on the next Render. This conversion applies only to View paths; durable Digests, Project display names, and Transcript/JSON metadata retain their original text. Layout literals and the path-valued `parent_dir`/`project_dir` variables alone define directory structure. The layout `project` is the collision-safe Project name (the Project directory name), so path layouts get the same case-collision protection as the default layout; it differs from the display name only for a Native Project whose name the collision rule suffixes or respells (ChatGPT Project `axon notes` beside Name Table `Axon Notes` lays out as `axon notes@<hash>`). Templates and Transcript/JSON metadata keep the display name. Navigation and hierarchy references use the resulting resolved paths.

### Non-functional

- **Official releases**: version tags `v<Cargo.toml version>` produce GitHub Releases after locked native-runner tests, lint, formatting, and release builds. Supported assets are `agent-sessions-<version>-aarch64-apple-darwin.tar.gz` and `agent-sessions-<version>-x86_64-unknown-linux-musl.tar.gz`, each containing the executable at its root, plus `SHA256SUMS`. Linux links statically with musl, bundled SQLite/zstd, and rustls TLS; macOS depends only on system libraries. Public releases carry GitHub build provenance; private releases skip attestations. `--version` reports the Cargo package version and stays identical across platforms for the fleet handshake. Consumer installs and scheduled commands use `$HOME/.local/bin/agent-sessions`; mixed-platform SSH Hosts require manually installing the matching asset of the same version at `remote-bin` before upgrading the central Host. Source builds use `--locked`. PR and main-push CI checks both platforms. Both workflows use the exact Rust version/components/targets in `rust-toolchain.toml` and full action commit SHAs; checkout does not persist credentials. Tests and build scripts have no OIDC or attestation write permissions; a separate download-only attestation job gates publication. Releases changing behaviour must bump the package version so version-based fleet redeployment sees the change. See [RELEASING.md](./RELEASING.md).

- **No services.** The archive is a directory: durable Capture, Session Media, Digest, and Project Assignment files plus configuration and one rebuildable SQLite file ([ADR-0001](./docs/adr/0001-capture-files-are-the-only-source-of-truth.md)). Backup = copy the directory. No Postgres, no daemon, nothing to operate.
- **Read-only on native Stores.** Never take write locks on live editor/agent/Orchestrator databases. SQLite is opened with the native library's read-only flag inside a consistent read transaction; files are only read. A Store whose WAL still has content is never opened `immutable` (that would hide live writes). An idle Store whose WAL is absent or empty may retry `immutable` so read-only mode can proceed without creating a `-shm` file. T3 auth/secrets/config and best-effort logs are outside the Store surface selected for Capture.
- **Bounded memory.** Stream, never slurp: single native files reach ~76 MB and stores reach GBs.
- **Cheap incremental runs.** Enumerate before hydrating: mtime gates, date-partitioned directory pruning (Codex is `YYYY/MM/DD`), SQL-side date filtering for Cursor. A scheduled run that finds nothing new should cost ~nothing. Pruning must never trade away growth: Codex day directories are pruned by *directory* mtime (appends bump a file's mtime, never its directory's), so every already-captured native path is additionally re-stat'd directly — one stat per Session — and re-enumerated on any mtime/size change.
- **Single static binary** (Rust, [ADR-0003](./docs/adr/0003-rust.md)) — required by the self-deploying pull model.
- **Durability first.** Irreplaceable native evidence is stored in compressed Capture files; Digests, Project Assignments, and Session Leads are plain files beside them. Back up captures/, media/, digests/, assignments/, leads/, lead-feeds/, and config.toml; archive.db and Views are disposable.

## Architecture

Cursor's optional per-Host Store override is `cursor-root`; it names the
`state.vscdb` file directly (the XDG Cursor path is the default). T3's
`t3-root` names its base directory; the production Store is
`<t3-root>/userdata/state.sqlite` plus referenced files under
`<t3-root>/userdata/attachments/`.

```
fleet hosts (stateless)                central host (cron, 1–2×/day)
┌──────────────────────┐               ┌────────────────────────────────┐
│ Stores → Adapter:    │  ssh + stdout │ pull → ingest → extract        │
│ enumerate → capture  │ ─────────────▶│                                │
│ → export Bundle      │               │ archive/                       │
└──────────────────────┘               │   captures/<host>/<source>/…   │  ← source of truth
                                       │   digests/<source>/<id>/…      │  ← durable, paid-for (ADR-0005)
                                       │   assignments/<source>/<id>.json │  ← durable Project Assignments
                                       │   archive.db (rebuildable)     │  ← Conversations, index, FTS, Bookmarks
                                       │   views/                       │  ← rendered Transcripts
                                       └────────────────────────────────┘
```

Two layers with opposite change rates: Captures are schema-free and absorb vendor churn; the Conversation schema is deliberately narrow (user, Agent, assistant, subagent links) and stays stable for years. Digests sit beside Captures as durable model output, never regenerated by rebuild. Project Assignments are durable classification input; configuration supplies reusable rules and display names. SQLite and Views remain reconstructible from these inputs.

Agent Captures extract to per-Host Session projections; Orchestrator Captures extract to per-Host Orchestrator projections and exact Link facts. Global resolution first elects each projection winner, then attaches resolved Augmentations to canonical Sessions. Render reads only those regenerable results—never a live agent or T3 Store.

## Non-goals

- No push from remotes; no credentials for the central archive on fleet machines.
- No wide "lossless canonical schema" for all native event types — that treadmill is the thing ADR-0001 rejects.
- No duplicate T3 Conversation for a linked agent Session, fuzzy Orchestrator linking, or text/timestamp-based cross-source Message merging.
- No writing to, cleaning, or managing native Stores.
- No always-on service, server database, or cloud dependency.
- No Digest of Subagent Sessions or of agent-to-agent exchange; the user's conversation is the value.
- No writes to native Stores except the explicit Title Write-back command (ADR-0006); `pull`, `digest`, and `render` never write a Store.

## Open questions

- Eager vs lazy Transcript rendering on ingest (freely reversible; decide during implementation).
- Retention/compaction policy, if any — current sizes (~6 GB raw fleet-wide, ~10:1 zstd on JSONL) suggest none is needed for years.
- Decide whether token counts belong in Transcript Views.

## Session Leads

A Session Lead declares that an agent led a Session, independently of Message roles or Subagent relationships. Import from explicit `[[lead-feeds]]` configuration through `leads sync --archive <dir> [--feed <name>]`, using the exact tool-neutral [Session Lead Feed v1](docs/session-lead-feed.md) contract. No producer-specific names, endpoints, or defaults. Consumers ignore unknown response fields; producers ignore unknown query parameters. Known fields remain strict: names, Host, and Origin values cannot be empty, and native identities cannot contain control characters. Sync lead-validation errors name the offending cursor and field. `leads list` and `leads show SOURCE:NATIVE-ID` inspect durable declarations.

Complete latest declarations live in `leads/<source>/<identity-component>.json`; per-feed Bookmarks in `lead-feeds/<identity-component>.json`. Files are authoritative and atomically published under the Archive writer lock. Validate whole pages, publish leads, upsert only that page into the rebuildable SQLite index, then advance the Bookmark. Fail explicitly on protocol, HTTP, config, or storage errors; rerunning replays uncommitted pages. Later declarations replace earlier ones by feed order, never timestamp; multiple feeds import in config order with the latest imported declaration winning. Leads are never deleted and may precede Captures; exact `(Source, native id)` matching ignores optional Host provenance.

Rebuild indexes pending and matched leads from files without contacting producers. Dotfiles are ignored; unexpected entries are skipped with warnings during file discovery and `leads list`. Malformed canonical lead files remain errors on rebuild. Render, List, and Show read the committed SQLite index; interrupted page publication is repaired by rerunning Sync, and out-of-band file edits require Rebuild. Removing a feed from config after a failed index refresh also requires Rebuild, since its durable page can no longer be replayed by Sync; removal does not delete archived declarations. Read-only lead inspection on a pre-leads index fails with instructions to run Pull or Rebuild first. Render supplies `session.led_by` as null, `{"kind":"agent"}`, or `{"kind":"agent","name":"Coordinator"}` to every Session/Session Day template and JSON View. When supplied, `session.led_by.origin` carries the complete producer-defined string map. Optional `origin.requestedBy` must contain a nonempty producer-defined source and nonempty native id separated by a colon; malformed values fail lead validation with cursor and field. For each delegated Session Day, Render selects the Requester Session's rendered Session Day on the same configured Workday, otherwise its latest rendered Session Day before that Workday; only paths in the current render plan qualify. If none qualifies, omit the link. Lead `recordedAt` is declaration replacement metadata only, never temporal attribution or a render anchor; re-emission alone cannot change the link. `session.requested_by` is null when unresolved (including absent or omitted requester Sessions, no rendered day on or before the delegated Workday, or Session-level Views), otherwise a note reference with `stem`, relative `path`, `workday`, `title`, `source`, and `native_id`. Unknown requester sources or identities remain unresolved without failing Sync, Rebuild, Render, List, or Show. A requester naming the lead's own Session remains unresolved, including references to another day of that Session. Never select a future requester day. Later renders resolve newly available notes idempotently, preferring a newly rendered same-day note over an earlier day. Bundled templates emit `session-requested-by: "[[<stem>]]"` for resolved references and `session-t3-thread: "<machine>:<t3ThreadId>"` for T3 origins carrying those fields. Content comparison updates affected notes after a declaration changes. Templates own authorship presentation and remain user-owned; no Message-role rewrite or inferred human authorship. Views must not overlap either lead directory. Backups include leads and their Bookmarks.

### T3 v2 upgrade operations and imported evidence

T3 Capture revision 4 includes `orchestration_v2_legacy_imports`. For an imported Thread without any root Provider Thread rows, extraction carries exact link facts and missing recovery Dialog from the latest legacy Prior Revision of the same Host/Thread. Retained Captures are the sole historical authority; never read live legacy Thread tables. Native v2 references suppress inheritance even when malformed. Pull, Bundle ingest and Rebuild use this same durable extraction path.

T3 Capture revision 5 uses only the current v2 checkpoint projections. Live enumeration and Capture exclude the obsolete v1 `checkpoint_diff_blobs` table removed by T3 migration 63 (`DropUnusedV1Projections`); its presence in an older Store is irrelevant. There is no separate old-schema live reader. Required v2 tables and columns remain mandatory, including in empty Stores; incompatible schemas fail explicitly. Historical Captures remain readable without consulting any live Store.

`pull --full-source SOURCE` resets that Source's Bookmarks on every configured Host under Pull's writer lock, leaving other Source windows unchanged. Remote exports omit `--since`; replay is idempotent. Fleet `--version` identity includes semver plus build git hash (and a dirty-source fingerprint for development builds), so rebuilding the same package version redeploys changed code. Back up the complete Archive before the v2 deployment; rollback requires restoring that backup because older binaries do not understand generations.

Unfiltered Push Titles reports T3 planning failures per Source and continues healthy Claude/Codex plans; the CLI exits unsuccessfully after reporting partial results. Bare Export isolates Source schema failures and counts them in the Bundle manifest. Filtered requests fail explicitly. T3 title dispatch sends trimmed titles, exposes only failure tags/codes, and uses bundled webpki roots for HTTPS origins. Both Codex and Claude strong native IDs must have UUID syntax. Render protects T3's `userdata` hierarchy while allowing generated Views in its worktrees.

## ChatGPT externally supplied evidence

ChatGPT is a Hosted Source collected by ordinary Pull from the browser companion's read-only native Store. Each `*.meta.json` observation requires `url`, `sha256`, `capturedAt`, and `accountId`; the Adapter groups response files by native conversation identity, verifies their hashes, and accumulates evidence in Captures. The contributing machine is the Host and account identity is in the Capture sidecar. `[host].chatgpt-root` configures this Store; absent configuration uses `~/.local/share/chatgpt-tools/captures`. Pull and Export accept `--chatgpt-root`. Collection runs independently and finishes before the nightly Pull. There is no `ingest-browser` command or alternate browser extraction pipeline.

`chatgpt ingest-export --archive DIR --zip FILE --account-id ID` is a one-time import, streaming conversation objects from ZIP shards under one Archive lock, with ordinary Adapter extraction. It never releases/reacquires that lock between preservation and indexing. Partial native evidence merges additively on local and Bundle ingest. Export media metadata with no originating conversation is preserved verbatim as a catalog Capture and counted as unassigned in the media report. Metadata naming an absent conversation remains a media-only Capture. Neither creates a Session or blocks conversation checkpoints. Catalog changes refresh native Project projections without re-extracting unchanged Dialog.

## Rendered Dialog grammar

Dialog is line-framed pseudo-XML containing Markdown, not a general XML document. Reserved tags are `user`, `agent`, `assistant`, `parent`, `goal`, `goal-continuation`, `subagent`, `gap`, `tool-calls`, and `branches`. Every generated delimiter occupies an entire line at column 0. Paired elements have a blank line after the opening delimiter and before the closing delimiter; self-closing elements have no body. Attribute values are double-quoted XML values, except the bare nonnegative integer `count` in the established `<tool-calls count=N />` seam. Unknown Message attributes and malformed framing are parser errors.

```text
message = role-open LF LF body LF LF role-close LF
role = user | agent | assistant | parent
role-open = "<" role attributes ">"
role-close = "</" role ">"
attributes = [kind]
goal-body = "<goal>" LF LF body LF LF "</goal>"
continuation-body = "<goal-continuation />"
```

Optional `kind` names `goal`, `goal-unresolved`, or `goal-continuation` (absent means `dialog`). Goal bodies wrap their objective in `<goal>`; an unresolved objective additionally has the generated availability comment. A Goal Continuation requires its preceding objective when parsed. `<parent>` decodes to a canonical user role within the caller's retained Subagent context.

A content line resembling a reserved delimiter at column 0 is prefixed with one backslash, including when it already has backslashes before such a delimiter. Parsing removes exactly one escaping backslash. This applies inside code examples too; inline and indented tag text remains literal. Arbitrary JSON authored as reply text is unchanged. Interior Message whitespace is preserved; trailing Message whitespace is omitted in the View. Verification compares the displayed body with the archive Conversation’s display projection, then restores its exact Message text including original trailing spaces and newlines. The generated repair comment sits outside the role wrapper.

`<gap duration="…" workday="…" />` is navigation metadata; either attribute may be absent. Opt-in Action seams use `<tool-calls count=N />`, including a trailing seam. `<subagent>` contains the resolved Subagent link. `<branches>` contains continuation links and occurs at a Shared Segment's end. Navigation blocks never become Messages or Digest input. The shared `parse_dialog` API reads displayed roles, kinds, text and optional Action seams. `parse_dialog_against` verifies these against the canonical archive/database Conversation, then restores its exact text, timestamps and Action counts. Round-trip coverage verifies rendered Dialog against that Conversation with its unchanged Session frame. Source-specific rich presentation and generated References are display projections, not a reversible native-format encoding.

`render --json` emits the versioned `asessions-render-v1` report. Each changed
file records creation/update/removal, before/after SHA-256, and `form_only`.
Form-only means unchanged Dialog, Digest and media identity with changed layout,
template, navigation or renderer output. A disposable SQLite comparison cache
proves unchanged semantic inputs against the previous output hash. Unrecognized
or externally edited files are conservatively content changes; an uncached
transcript can be compared through its parsed Dialog and visible Digest.

Covered ChatGPT snapshots retain only their non-message native metadata, including
`update_time`, so retained pages and Versions keep their owning revision. Native
response hashes cover exact bytes, including surrounding JSON whitespace.

Multi-day Fork files use an available main-path Locked Title when a Shared
Segment has no Digest of its own; session-unit Path Ends load their first
available Day Digest through `session.digest`. Preceding Shared Segments use
the same input budget as the continuation. Digest cache/publication identity
includes the Path End. Opening edits retain orphaned generated-media references
on the oldest Session.

Media materialization rejects symlink directories beneath the View root.
Embedded-image references use native Message identity (record ordinal when
no native ID exists) and native block content; absent Archive bytes render
missing-image text. Bundle media references must match validated object bytes
and metadata, and cannot replace conflicting object metadata.

ChatGPT starting model comes only from the first visible assistant Message's
`metadata.model_slug`, never the current conversation default. Validated
ordered citation rebasing takes precedence over stale exact reference entries.
An internal/hidden export sibling cannot certify visible Versions coverage.

All ChatGPT Project evidence paths use the same native Project namespace check:
`g-p-` followed by 32 lowercase hexadecimal digits. Catalog paths cannot turn
an arbitrary custom Gizmo ID into a Project.

Preflight Input Token Counts include measured Session title requests as well as Session Day requests, attributed to their Source. A title-only retry reports its title input tokens even when there are no Day Digest previews; unknown future outputs remain uncounted.
